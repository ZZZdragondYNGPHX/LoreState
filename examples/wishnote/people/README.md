# 缄愿笔记 · LoreState 统一状态版 2.0

本版不兼容旧 LoreState 聊天与配置，请使用新聊天。下面的转换工具仅用于原始 WishBook 文件，不是运行时兼容层。

这是原世界书＋正则＋快速回复方案的技术迁移。愿望及人格叙事规则保留，状态维护改由酒馆助手内的 LoreState prototype-v0.4.0 执行。不依赖 MVU 或额外模型调用。旧工程与 examples/wishnote 分支均保留。

2.0 的远程脚本固定 prototype-v0.4.0 标签；CDN 无法访问时使用离线备用脚本。

## 新聊天安装

1. 导入 `dist/缄愿笔记_LoreState统一版_2.0.json` 世界书，绑定到目标角色。
2. 在酒馆助手的角色脚本中导入 `dist/缄愿笔记_角色脚本.json`，启用角色脚本。HTML、三个人物栏目、统一协议与世界书关联已配好。CDN 无法访问时用离线备用版，二选一。
3. 对这张卡停用原 v8 世界书、整套缄愿笔记维护快速回复、13 条旧正则，以及旧 WishNote/LoreState 扩展的聊天维护。全局若有其他 LoreState 脚本也需停用，不能同时维护本聊天。不要删除原文件和旧存档。
4. 开始新聊天，从魔法棒进入 LoreState 设置，确认世界书条目“LoreState · 愿档状态栏”，点击保存。此操作自动添加两条局部正则；如局部正则未启用，在酒馆启用。dist 中另有两份正则作手动导入备用，同 ID 不要重复添加。
5. 正常游玩。首次没有愿效人物时允许空的 `<LoreState version="2" mode="full"></LoreState>`；出现愿望时建档，以后只更新变化栏目。人物界面显示已成事实、持续条件、生效关联。

状态栏条目 UID 6 默认禁用，是让脚本读取并单独注入的配置来源，不能据此判断安装失败；不要再开启成另一份常驻协议。UID 8 续页规则改为常驻，避免旧标签过滤后失去触发。0–5 的内容与触发元数据未改。

## 和旧版的差别

- WishBook/WishDelta/ArchiveQueue 改为一个 LoreState 更新块。
- 离场记忆保留在聊天中，不再由 QR 向 Chat Lore 反复写摘要；只向模型提供索引，明确提及编号/唯一姓名时预取。
- AI 临时让未预取人物回归时，先空 delta 唤醒，下一轮才允许修改其状态。不能保证同一轮自动补读冷档。这是迁移后的明确时序差异。
- 原“立即维护/缺档恢复”改为按消息回放及“重新读取当前聊天状态”；原“解析 Queue/愿档状态”改为界面中的错误提示与本地离场资料查看。
- 备份请导出完整聊天；角色脚本/角色卡导出只携带配置，不含游玩记录。删除建档楼层后不能靠末尾快照伪造原历史。

## 可选的旧 WishBook 离线转换工具

不直接在旧聊天中启用新协议。先备份完整聊天、Chat Lore，再取得当前选中分支最新完整 WishBook（或确认有效的旧检查点）以及冷档世界书导出文件。

在 LoreState 源码仓库根目录运行以下命令（安装包不包含开发工具依赖）：

```sh
node scripts/migrate-wishnote-people.mjs 热档.xml 冷档世界书.json 转换预览.json
```

没有热档或冷档输入时该位置填 `-`。输出文件拒绝覆盖，包含新初始化 XML、状态预览、告警及原文备份；不调用模型、不写酒馆。冷档摘要不自动拆分，原文放入已成事实。热冷同号采用指定热档并保留冷档备份，需人工核对。

确认预览后，在新聊天第一条 AI 消息（非 0 层开场白）中保留正文并附上输出的 `xml`，点击重新读取。这里是手工建立历史起点，不要求模型抄写旧档；之后使用 delta。旧聊天正文不会自动复制，人物稳定识别信息可在这条初始化消息中补充。没有旧聊天输入时，交付只证明新聊天组件迁移，不代表你的实际旧存档已迁入。

## 开发与验证

`node scripts/build-wishnote-people.mjs` 生成 dist。规则源为 rules.txt，样式源为 status.html。构建读取固定旧世界书，不改原文件。`npm test` 检查叙事条目原样保留、脚本配置、字段一致和冷热迁移。

本包为世界书与脚本组件，不虚构完整角色卡。实际宿主导入和剧情可靠性需单独验收；没有把它自动安装到你正在玩的卡，也没有自动停用旧组件。
