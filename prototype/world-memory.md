0.8.0 候选补充：有效读取凭据允许已完整预取的冷档当轮更新；无凭据仍遵循下文空唤醒规则。作者可配置初值和字段约束，历史快照正文去重。详见 [0.8.0 使用与统一验收](../docs/0.8.0使用与统一验收.md)。下文是 0.7.0 基础协议，新增行为以上述说明为准。

## 数据与加载

- `Shared`：常驻栏目，每轮提供给模型，只有变化时更新。
- `Entity`：人物、国家、组织、地点、物品、事件或作者自定义类别。所有实体共用模板定义的文字栏目。
- `presence="active"`：热档，每轮完整提供。
- `presence="cold"`：冷档，完整文字保存在聊天状态及快照中，提示中通常只有少量索引。不会压缩或删除本地事实。
- `type="事件" pending="true"`：未完成活动事件，必须保持热档。承诺、战争影响、倒计时等应独立建档，避免随参与者转冷而丢失。

目前按整个实体控制冷热，不单独切换实体内某个栏目。复杂国家的百科资料与当前战争影响可以拆成国家实体和独立事件，用 `links` 关联。没有自动后台模拟、额外模型请求或语义检索。

状态为 `{version:3, shared:{}, entities:{}}`；脚本配置与聊天使用 `lorestate_world_v3` 命名空间。schema 为 `{shared:[...], entity:[...]}`。旧缄愿笔记示例与转换工具已从当前主线移除，不参与 v3 构建；历史发布标签仍按其原始内容保留。

## 标签例子

以下例子的模板栏目为：公共 `地点、时间`；实体 `概况、当前状态`。

```xml
<LoreState version="3" mode="full">
  <Shared><地点>港口</地点><时间>第三天清晨</时间></Shared>
  <Entity id="N01" type="国家" name="北境公国" identity="北方公国" mode="full" presence="cold" confirmed="第二天">
    <概况>与南方暂时停战</概况><当前状态>边境保持戒备</当前状态>
  </Entity>
  <Entity id="P01" type="人物" name="林舟" identity="港口书商" mode="full" confirmed="第三天清晨">
    <概况>经营码头书店</概况><当前状态>正在备货</当前状态>
  </Entity>
  <Entity id="E01" type="事件" name="送货承诺" identity="林舟给旅人的订单" mode="full" pending="true" links="P01" confirmed="第三天清晨">
    <概况>林舟承诺送来十本书</概况><当前状态>第四天中午交付；尚未完成</当前状态>
  </Entity>
</LoreState>
```

离场或暂时无关时转冷，正文和完整档案保留：

```xml
<LoreState version="3" mode="delta">
  <Entity id="P01" mode="delta" presence="cold"/>
</LoreState>
```

事件 E01 继续每轮提供，并可通过关联取回 P01。事件完成后可以更新结果并转冷：

```xml
<LoreState version="3" mode="delta">
  <Entity id="E01" mode="delta" pending="false" presence="cold" confirmed="第四天中午">
    <当前状态>十本书已经交付</当前状态>
  </Entity>
</LoreState>
```

冷档直接更新栏目会被拒绝，即使本轮已预取。先空 delta 唤醒，下一轮再更新；无依据的离场变化保持未知。`links=""` 清空关联，遗漏属性或栏目表示保留；`action="remove"` 明确删除栏目内容。每轮更新原子提交，任一错误不会写入半份状态。

## 召回与预算

1. 当前热档、未完成事件，以及用户输入明确提到的编号或唯一名称，作为本轮完整资料。编号按边界匹配，名称采用至少两个字符的字面匹配；不解析代词或别名，同名对象请用编号。
2. 从上述对象沿 `links` 向外一跳，额外取回最多 8 个对象；不递归。每个实体最多 8 个不同关联，编号必须已建档或在本轮同时建档，不允许自关联。
3. 其他冷档最多展示 24 条索引，并报告未展示数量。精确编号或唯一名称仍可检索完整本地档案，不受索引是否展示影响。
4. 总提示上限 24000 字符。超限先撤下索引，再撤下可选关联对象的完整资料，并说明未加载编号。常驻、热档、活动事件和明确召回不能截断；仍超限则报错，请降低必需上下文。

最多 500 个实体，本地当前状态最多 100 万字符，每类最多 32 个文字栏目、每栏目最多 6000 字符。完整历史快照仍可能占较多存储，冷热节约的是每轮模型上下文，不是历史快照容量。索引不是完整事实，模型不得据此编造旧记录。

`confirmed` 保存作者/模型提供的已知剧情时间；未提供则为未知。脚本自动记录 `confirmedFloor`，表示最后新建或更新事实的消息楼层。转冷、空唤醒、关联调整和提示预取不刷新事实时间。事实再次修改却未提供剧情时间时，清除过时的 `confirmed`，保留新的来源楼层。上述楼层信息只读，不是模型可输出的属性。

## 模板与验收

使用一个 `data-lore-entity` 重复容器，内含 `data-lore-field="栏目名"`；容器外的字段为公共栏目。实体可绑定 `data-lore-name`、`data-lore-id`、`data-lore-identity`、`data-lore-type`、`data-lore-confirmed`。状态栏展示热档，本地冷档折叠区可查看全部冷档。

自动检查：`npm test`、`npm run check`、`npm run build`、`node scripts/test-browser.mjs`（默认 Windows Edge，可用 LORESTATE_BROWSER 指定浏览器可执行路径）。浏览器回归使用模拟酒馆助手 API，不代表真实酒馆验收。
