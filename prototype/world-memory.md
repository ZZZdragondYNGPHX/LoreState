# LoreState v3 世界状态、模块与冷热档 · 当前 0.12.1

本文是当前 Tavern Helper 主线的**协议参考**。`0.7.x` 时代“所有实体共用同一模板栏目”“预取冷档仍不能当轮更新”等旧说明已经不再代表当前实现。

当前固定稳定版是 **`0.12.1`**；作者入门见 [docs/作者入门.md](../docs/作者入门.md)，模块写法见 [状态栏条目创作指南](../docs/状态栏条目创作指南.md)。

## 三层职责

LoreState 当前把三件事分开：

1. **模块条目 / DataSchema**：定义公共栏目、模块、各模块字段和自然语言更新规则。
2. **v3 状态**：保存当前共享事实、实体档案、冷热状态、关联、事件等。
3. **Template API v2**：只决定状态如何显示，不决定保存哪些字段。

EJS / 动态世界书又是第四个可选只读消费者：读取可靠 v3 快照，根据区间/阶段输出世界书文字，但不写状态。

## 模块条目

当前条目第一行：

```text
【LoreState模块 v1】
```

示例：

```text
【LoreState模块 v1】
【通用规则】
只记录正文已经确认的持久事实；猜测、传闻和计划不写成既成事实。
【公共栏目】
栏目：地点、时间
明确移动或时间推进时更新。
【模块：人物】
栏目：身体状况、当前目标
受伤或恢复时更新身体状况；明确改变意图时更新当前目标。
【模块：物品】
栏目：持有者、完好状况
交付、遗失、损坏或修复时更新。
```

人物、物品、国家、事件、组织、地点等模块**可以拥有不同字段**。同名字段也可以出现在不同模块；它们仍属于各自实体。

DataSchema 来自条目，不来自 HTML。

## 状态形态

概念状态：

```json
{
  "version": 3,
  "shared": {
    "地点": "白帆港",
    "时间": "第三天清晨"
  },
  "entities": {
    "P1": {
      "id": "P1",
      "type": "人物",
      "name": "爱丽丝",
      "identity": "港口向导",
      "presence": "active",
      "fields": {
        "身体状况": "健康。",
        "当前目标": "带队前往旧灯塔。"
      }
    }
  }
}
```

实体 ID 是稳定路径。EJS 等读取使用 `entities.P1.fields.身体状况`，不是按名字另建变量映射。

## full / delta

第一次建立状态使用外层 `mode="full"`；以后普通更新使用 `mode="delta"`。

概念 full：

```xml
<LoreState version="3" mode="full">
  <Shared><地点>白帆港</地点><时间>第三天清晨</时间></Shared>
  <Entity id="P1" type="人物" name="爱丽丝" identity="港口向导" mode="full" presence="active">
    <身体状况>健康。</身体状况>
    <当前目标>带队前往旧灯塔。</当前目标>
  </Entity>
</LoreState>
```

概念 delta：

```xml
<LoreState version="3" mode="delta">
  <Shared><地点>旧灯塔入口</地点></Shared>
  <Entity id="P1" mode="delta"><身体状况>右手轻微擦伤。</身体状况></Entity>
</LoreState>
```

已有字段遗漏表示继承旧值。一个字段出现时，它的文字是该字段**新的完整当前值**，不是字段内部的自动 patch。

新实体第一次建档使用实体 `mode="full"` 并满足自己模块要求的字段；已有实体使用 `mode="delta"`。

多个模块可以在同一个 LoreState 块中更新。整批更新原子提交：任何结构、schema、读取权限等错误都会拒绝整轮，不保存半份状态。

真实生成还可能包含当轮 read receipt 等属性；模型必须按实际提示复制，不应把本文概念示例当成固定可伪造凭据。

## active / cold

实体按整个档案控制冷热：

- `presence="active"`：热档，属于当前常用上下文；
- `presence="cold"`：冷档，完整事实仍保存在本地状态/历史，但通常不每轮完整发送给模型。

转冷不是删除。遗漏字段继续保留。

```xml
<LoreState version="3" mode="delta">
  <Entity id="P1" mode="delta" presence="cold"/>
</LoreState>
```

以后被准确提及、被当前对象通过有限关联带出，或满足其他读取条件时，可以把完整冷档重新提供给模型。

## 冷档读取与 read receipt

当前实现允许**本轮已经完整、可靠加载的冷档**在有效读取凭据保护下当轮更新。read receipt 对应生成前状态、配置和实际加载对象；它不是模型自行宣称“我看过了”的开关。

原则：

- 索引不等于完整读取；
- 被预算撤下的对象不算已读；
- 查看本地冷档 UI 不等于给模型发放读取权限；
- EJS 读取快照也不发放状态写权限；
- 有效 receipt + 本轮真实加载对象才能通过相应冷档写入校验；
- 历史状态、配置或分支变化会使依赖旧前态的凭据失效；
- 不允许通过删属性、手工伪造 receipt 绕过校验。

旧历史标签在兼容范围内仍可回放，但不能凭空获得当前读取权限。

## links 与有限关联

实体可以通过稳定 ID 建立 `links`。关联用于本轮需要一起读取的对象：

- 有向；
- 一跳；
- 不无限递归；
- 数量有实现上限；
- 不应把整个关系网全部挂上。

例如“送货事件”链接负责商人和货物即可；不需要顺带链接商人的国家、组织和所有联系人。

清空 links 属于显式状态变化；遗漏表示保留。

## 活动事件

承诺、追杀、战争影响、倒计时、截止任务等“参与人物离场后仍会继续影响剧情”的事实适合独立事件实体。

事件规则建议记录：

- 事项/条件；
- 当前进展；
- 必要的参与对象 links；
- 是否仍未完成。

到达时间点只意味着剧情应该处理，不等于程序自动判定完成。LoreState 没有后台世界模拟，也不会自己推进战争或任务。

只有正文明确完成/取消后，事件状态才应该更新并按规则转冷。

## confirmed 与历史来源

实体可保存作者/模型提供的剧情确认时间；运行时也会记录事实来自哪个消息楼层。单纯转冷、空唤醒、关联调整或提示读取不应冒充新的事实确认。

状态的权威历史仍来自当前聊天选中回复分支的 LoreState 更新 + 合法快照/回档基线。编辑、删除、重抽和分支变化会重新经过回放校验。

## 隐藏楼层

隐藏助手只改变哪些旧正文进入模型上下文，不等于从本地状态历史删除消息。

当前 0.12.1 包含隐藏历史兼容：属于当前选中分支的隐藏 AI 楼层仍参与状态回放、诊断和快照。单纯改变隐藏范围不会让有效历史消失；真正编辑/删除/切分支仍会触发校验。

详见 [隐藏助手兼容与更新](../docs/隐藏助手兼容与更新.md)。

## 快照与回档

聊天可以保存状态快照并恢复为新的回档基线。回档不会删除旧正文；它改变 LoreState 从哪里继续解释后续状态。回档后的新回复从恢复状态继续。

快照属于聊天数据，不属于角色卡脚本配置；角色卡导出不能代替聊天备份。

历史编辑、删除或回复分支变化可能使旧快照/凭据不可再安全使用。完整 UI 行为以当前运行代码和 [常见问题与试卡清单](../docs/常见问题与试卡清单.md) 为准。

## Template API v2

当前展示不再使用旧 `data-lore-entity` 单一实体模板。

公共字段：

```html
<span data-lore-shared="地点"></span>
```

人物区域：

```html
<article data-lore-each="人物">
  <h3 data-lore-name></h3>
  <p data-lore-field="身体状况"></p>
</article>
```

冷档可以由作者使用 `data-lore-presence="cold"` 自定义布局。HTML 可以省略某字段，但这不会从状态删除字段。

完整接口见 [HTML 模板适配指南](../docs/HTML模板适配指南.md)。

## EJS / 动态世界书

0.12.0 起，ST-Prompt-Template 可通过 LoreState 只读桥接读取同一可靠回放事实源：

```ejs
<% if (LoreState.ready && lsRange("entities.P1.fields.好感度", -100, -50)) { %>
当前关系处于明显敌对区间。
<% } %>
```

桥接不写状态、不另建 stat_data、不自动改世界书，也不绕过 read receipt。当前固定安装用 0.12.1。详见 [EJS 指南](../docs/EJS动态世界书.md)。

## 预算与失败原则

当前实现对条目、提示、实体数量、字段长度、模板 DOM/克隆和本地状态都有硬上限。准确常量以运行维护源为准。

总体原则：

- 超预算时优先撤下可选索引/关联资料；
- 不能静默截断必须完整的当前事实；
- 无法形成可靠生成前态时中止/返回空态，而不是猜；
- 不能把缓存旧状态冒充当前事实；
- 一个更新块任一校验失败时不部分提交。
