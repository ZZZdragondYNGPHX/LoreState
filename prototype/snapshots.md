# 0.6.0 历史快照与状态回档

0.8.0 补充：历史版本全部保留，存储改为正文与配置内容去重；旧快照自动无损转存。读取凭据与快照共用状态正文，管理器显示容量；旧脚本不能解释新存档，回退需要升级前聊天备份。详见 [0.8.0 使用与统一验收](../docs/0.8.0使用与统一验收.md)。下文保留当时回档行为说明。

入口：魔法棒 → LoreState → 诊断修复 → 历史快照与回档。选择快照，点击“预览快照回档”，核对完整状态后“确认回档”。

每个参与更新的 AI 楼层保存完整公共状态、全部实体（包含冷档）、错误与最后正常楼层。当前选中的回复分支、原文或前置历史变化会形成新版本，已有版本不被覆盖。默认全部保留，聊天数据会随使用增长。

升级首次运行会从现存选中回复补建历史。无法找回升级前已删除或被覆盖的正文版本，也不会宣称保存未选中过的所有 swipe。快照属于聊天变量，不属于随卡脚本配置；仅导出角色卡不能代替聊天备份。

回档以聊天变量更新写入完整基线、当前状态和撤销信息。已有正文完全保留，截止确认回档时的旧消息不再作为回档后的状态增量继续重放；之后的新回复从恢复快照接续。旧剧情仍在聊天正文中，回档不会让模型自动忘记剧情。

“状态历史”表示原文回放；回档期间应有明确提示。快照预览显示保存版本，正文状态栏显示当前生效状态。存在错误缺口或与当前 schema 不兼容的快照不可安全恢复。

“撤销上次回档”只适用于回档后尚未产生冲突修改的情况；聊天变化后需重新预览保存快照。回档基线之前的正文被编辑、删除或切换分支时，应停止套用该基线并提示重新处理，避免悄悄使用错误历史。

当前额外模型重算、EJS 生成前态与隐藏历史也依赖同一可靠回放原则：无法确认前态/分支时宁可停止或返回空态，不把缓存旧状态冒充当前事实。

本地自动化不能证明宿主已经把聊天变量持久化到磁盘。真实酒馆的刷新重开、聊天导出再导入、长聊天容量和实际宿主时序仍需实机检查。
