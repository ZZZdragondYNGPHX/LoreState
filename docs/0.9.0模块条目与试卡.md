# 0.9.0 模块条目与试卡

0.9.0 是模块条目设计的历史版本。人物、物品、国家和作者自定义类别从这里开始可以拥有各自的栏目与更新规则。后续 0.11.x / 0.12.x 保留这一 DataSchema 思路，并在展示、外观制作和 EJS 上继续扩展。

## 当前版本如何直接试用这一模块设计

1. 在独立测试角色卡、新聊天中使用 [0.12.1 固定组件](../prototype/dist/0.12.1/lorestate-script.json)。只有明确要跟随开发时才使用 [main 组件](../prototype/dist/main/lorestate-script.json)。
2. 将 [完整模块条目示例](../prototype/module-example.txt) 放进一个世界书条目。避免同一段规则又作为常驻世界书重复注入；LoreState 会读取已绑定条目统一组装状态提示。
3. 打开 LoreState 设置，选择世界书和这条模块规则，点击 **确认绑定状态栏条目**。
4. 打开外观制作，使用 API 生成/修改 HTML，或直接使用 [紧凑日志](../prototype/module-example.html) / [旅途档案 HUD](../prototype/example.html)。当前模板必须是 Template API v2。
5. 预览并应用外观；首次使用回设置点击 **保存 HTML 并启用本聊天**。
6. 可选用作者初始档案提供明确初值；否则由首轮正文建立 full 状态。
7. 用“查看下一轮状态提示”检查实际发送的模块目录、规则、当前状态和读取资料。

下面的条目/加载机制仍是当前模块设计的重要基础；其中涉及当时 UI、组件版本或“当前”的描述均只代表 0.9.0 阶段。

## 条目格式

```text
【LoreState模块 v1】
【通用规则】
只记录正文已经确认的持久事实；猜测不写成事实。
【公共栏目】
栏目：地点、时间
明确移动或时间推进时更新。
【模块：人物】
栏目：身体状况、当前目标
受伤或恢复时更新身体状况；明确改变意图时更新当前目标。
【模块：物品】
栏目：持有者、完好状况
交付、拾取或遗失时更新持有者；损坏或修复时更新完好状况。
```

第一行是格式版本。标题单独占一行，不缩进、不加 Markdown 标记。每个公共或模块分区的首个非空行必须是 `栏目：`，栏目之间使用中文顿号 `、`；其后都是该分区的自然语言规则。通用规则、公共栏目可以省略，模块需要 1–16 个，不得重名。暂不支持分区嵌套。

模块名和栏目名使用文字或下划线开头，后续可用文字、数字、下划线、连字符，最多 40 字符。公共栏目最多 32 个；全部实体模块合计最多 32 个不同栏目名，每个模块至少一个。同名栏目可以出现在不同模块，值存于各自实体中。条目最多 24000 字符；实际组装后的规则和档案总预算也是 24000 字符，超限会中止生成。

栏目定义来自条目，而非 HTML。Template API v2 可以只展示部分字段、重复字段或省略整类；这些展示变化不改变 DataSchema。实际模块字段变更仍受已有配置保护；单独调整规则文字可以在后续生成时生效，不会重算历史语义。

字段约束继续配置于 `shared` 和 `entity`。`entity` 中某字段的必填、禁止删除和枚举约束只作用于含有该字段的类别；不同模块若使用同名字段，会共用这条约束，暂不支持同名字段按类别配置不同枚举。

## 每轮加载什么

- 通用规则、公共栏目规则、全部模块的名称与栏目目录始终提供。
- 首次建立状态时提供所有模块详细规则，便于正确初始化。
- 已有状态时，当前热档、活动事件、明确提及的实体及一跳关联完整档案，会带上其所属模块的详细规则。
- 冷档索引本身不触发详细规则，也不代表已经读取旧档。预算撤下可选完整档案时，同时重新计算所需规则和读取权限。
- 正文出现一个已声明但尚未有实例的类别，可以按目录和通用规则建立新档；需要“建档当轮就必须生效”的约束，应写进通用规则或机器字段约束。

例如热档只有人物、物品时，国家栏目目录仍在，但整段国家详细更新规则不一定每轮发送。这里没有代词/别名语义检索或后台自动模拟；规则是否省空间取决于本轮涉及类别。

没有声明“事件”模块时，不会要求 AI 自动建立事件实体。需要承诺、倒计时等持续影响的卡，应显式声明事件模块。

## 更新和展示

继续使用 `version="3"` 的 Shared / Entity 外层协议。实体 `type` 必须匹配已声明模块；新实体 full 填写自己模块要求的完整栏目，已有实体 delta 只写变化，遗漏保留。多个模块更新可以放在同一个 LoreState 块中，任何非法栏目或无效读取都会拒绝整轮提交。

概念示例：

```xml
<LoreState version="3" mode="delta">
  <Entity id="P1" mode="delta"><当前目标>返回书店</当前目标></Entity>
  <Entity id="I1" mode="delta"><持有者>守卫</持有者></Entity>
</LoreState>
```

真实生成必须遵守当轮提示提供的 read 凭据和完整协议；上例只说明跨模块原子更新。

当前 Template API v2 使用 `data-lore-each="人物"` 等分类区域，公共值用 `data-lore-shared`，实体字段在所属模块的 each 内用 `data-lore-field`。冷档可通过 `data-lore-presence="cold"` 由作者自行布局。详见 [HTML 模板适配指南](HTML模板适配指南.md)。

## 真实试卡清单

| 情境 | 应观察到的结果 |
| --- | --- |
| 新聊天首次生成 | 初轮规则齐全；建立的实体填写自己模块的完整栏目 |
| 纯人物对话，其他类别转冷且无关联 | 下一轮不必携带其他类别的完整档案 |
| 人物交付物品 | 正文与人物/物品状态一致，未变化字段保留 |
| 正文发现新物品 | 按物品模块创建档案 |
| 提到冷档的唯一名称或编号 | 按读取规则取回；写入仍受 read receipt 校验 |
| 未读取冷档却直接改字段 | 整轮拒绝，原状态不变 |
| 国家实体输出人物专用字段 | 报错，不保存半份更新 |
| 修改模块栏目后继续生成 | schema 保护应阻止无提示地改变结构 |
| 重抽、删尾、刷新、回档 | 按当前回复分支回放，模块和读取凭据一致 |
| 0.12.1 首次绑定非第一条规则 | 刷新/切页后仍保持正确绑定，不误用第一条 |

当前完整试卡清单见 [常见问题与试卡清单](常见问题与试卡清单.md)。历史 0.9.0 的自动证据仍保留在 [验证记录](../prototype/verification.md)，但不代表当前 0.12.1 已完成真实模型和长期人工游玩验收。
