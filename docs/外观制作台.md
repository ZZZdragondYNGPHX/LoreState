# 外观制作台 · 0.11.1 起（含 0.12.0）/ main

## 使用方法

1. 打开 LoreState → API 预设，保存模型来源、API 绑定与请求策略。也可跟随酒馆当前 Chat Completion 连接；此步骤可在首次启用状态栏前完成。
2. 在“设置”选择模块条目；已经完成配置的卡继续使用保存的栏目结构。
3. 进入“外观制作”，点击“描述风格 / AI 改稿”，填写想要的配色、布局、展示内容与移动端要求。
4. 选择从零生成或修改当前 HTML 草稿，点击“生成 HTML 草稿”。可查看实际发送的制作提示词；不会显示连接密钥。
5. 生成结果先通过安全、字段与合成数据渲染校验，再进入草稿和预览。可继续提要求改稿，或展开源码手动编辑。取消、失败和迟到结果不覆盖草稿。
6. 确认预览后点击“应用 HTML 草稿”；第一次使用需回“设置”点击“保存 HTML 并启用本聊天”。

### 保存与作用范围

- 草稿、风格要求与最近一次草稿撤回仅保留在当前脚本运行内存；关闭窗口保留，脚本重载/切卡可能丢失。要长期保留请另存命名预设。
- “另存为新预设 / 覆盖所选预设”只保存，不自动应用。“载入所选预设到草稿”只编辑；“应用所选预设”才切换当前外观。
- “应用 HTML 草稿”更新随卡外观，但不覆盖命名预设；同卡各聊天仍共用外观。本版没有新增每聊天独立皮肤。
- 手动编辑后旧预览会清除；重新预览不发送请求。最近一次草稿替换可撤回，但继续手动编辑后不会再盲目覆盖你的新内容。
- 风格生成复用已保存模型连接、采样、尝试次数、总超时和流式接收；不复用状态更新 prompt 或酒馆请求预设。流式结果完整校验后才进入草稿。
- 自动发送内容仅有栏目结构、风格和改稿时的 HTML；不自动附带聊天、真实状态或世界书原文。用户自己粘贴到风格/HTML 的私人文字仍会发送，请自行检查。

新增显隐和 class 映射接口见 [HTML 模板适配指南](HTML模板适配指南.md)。它们只解释声明式展示规则，不允许脚本、远程图片、网络、宿主操作或任意 CSS/HTML 属性写入。


## 范围与执行合同

- 基底：main / 8e28baa070841e281fa3b3113069e6d4210227eb；用户批准按推荐方案进行功能更新，角色切换问题延期。
- 形态：现有控制中心内的外观工作区 + 原生风格对话框，不另建应用或引入框架。
- 流程：已保存的 API 连接 → 风格描述 / 当前 HTML → 生成草稿 → 校验与预览 → 明确应用。
- 数据：API 密钥只留用户全局配置；风格和未保存草稿仅在本次运行内存中；HTML 预设继续随卡保存，同卡聊天共用外观，不新增聊天级外观覆盖。
- 兼容：XML v3、数据 schema、快照、回档和原初始化保护不变；Template API v2 新增显隐与 class 映射，旧 v2 模板不需重制。
- 红线：不执行模型脚本、不开放网络资源、不发送真实聊天/状态/整段世界书；不移动既有 tag、不安装、不实调付费 API；用户已追加授权本次完成后提交推送 main 并固定新标签 0.11.1。
- 明确延期：角色切换缺陷、栏目迁移、任意 JS、页签脚本、图片外链、排序、数值系统。

## 唯一实施检查单

1. 受控展示接口：条件显隐、字段值映射 class；验证字段作用域和安全预算。
2. 生成服务：独立 HTML 提示词，复用已保存连接/采样/超时/次数，不复用状态更新提示词或酒馆请求预设；失败及取消不写入。
3. 工作区：合并模板和预设，显示活动模板/草稿/API；风格弹窗、继续改稿、手工编辑、只读预览、显式应用。
4. 生命周期：请求与正文/状态更新互斥；聊天、草稿、栏目或 API 变更拒收迟到结果。
5. 验证：build → check → test → test-browser；最后检查差异与源产物一致性。

这是功能变更合同；布局搬迁复用原控件，不重写状态内核。分阶段按上述模块边界推进，原功能目标源代码/测试/文档共不超过 22 文件、1800 行变动；追加发布授权后允许同步活动文档、发布说明及固定版本输出，总范围上限 34 文件、2400 行，含必需生成物及用户既有删除状态的审计；超预算先检查范围，不扩增产品功能。持久子蓝图预算 0。
