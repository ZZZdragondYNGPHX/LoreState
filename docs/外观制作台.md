# 外观制作台 · 当前 0.12.3

外观制作台从风格描述生成 Template API v2 HTML，或基于当前 HTML 继续改稿。模型结果只进入草稿；通过本地字段/安全校验并由用户显式应用后，才会改变当前外观。

## 当前首次使用顺序

1. 打开 **LoreState → 规则配置**，选择世界书与模块条目。
2. 点击 **确认绑定状态栏条目**。
3. 打开 **LoreState → 模型连接 → 管理 API 预设**，保存用于外观生成的模型连接；也可以提前保存。
4. 进入 **外观制作**，选择从零生成或基于当前 HTML 改稿。
5. 填写布局、配色、展示内容和移动端要求，生成 HTML 草稿。
6. 校验、预览；需要时继续改稿或手动编辑。
7. 显式应用草稿；首次启用仍需 **保存 HTML 并启用本聊天**。

0.12.1 起，已确认的条目绑定在刷新和设置/外观切页后保持；原条目消失时会要求重新选择，不会静默改用第一条。

## 外观请求发送什么

外观生成复用已经保存的模型连接、采样、尝试次数、总超时和流式设置，但使用**独立 HTML 制作任务**。

自动发送：当前 DataSchema、你的风格描述、改稿时的当前 HTML。

不会自动发送：聊天正文、真实状态值、整段世界书原文或 API 密钥。你主动写进风格描述/HTML 的内容仍会发送给所选服务。

状态更新可以选择当前/指定酒馆提示词预设；外观制作仍使用独立 HTML 任务，不把角色卡/聊天历史当作状态更新 prompt 混进来。

## 草稿、预设和当前外观

- **生成 HTML 草稿**：只改草稿。
- **应用 HTML 草稿**：通过校验后设为当前随卡外观。
- **另存/覆盖命名预设**：保存预设，不自动切换当前外观。
- **载入预设到草稿**：只进入编辑态。
- **应用所选预设**：显式切换当前外观。

当前没有聊天级独立皮肤；同一角色卡的聊天共用随卡外观。

## 请求生命周期

切换聊天/角色卡、改变条目绑定/DataSchema、更换 API 配置、改变当前草稿或主动取消后，迟到结果不会覆盖新的上下文。正文生成、状态更新与外观制作之间有互斥保护。

## Template API v2 边界

外观仍受 [Template API v2](HTML模板适配指南.md) 的同一安全和字段限制：`data-lore-template="2"`、`data-lore-shared`、`data-lore-each`、`data-lore-field`，以及 count/empty/presence/select-id/limit、条件显隐和 class 映射。

模型生成的 JavaScript、远程资源、iframe、表单等不会因为来自“外观制作台”就绕过校验。

## 换皮肤与换栏目

换配色、布局、显示顺序或隐藏部分字段，不改变 DataSchema，可以继续使用现有状态。

增删/改名模块或栏目属于 schema 变化。0.12.3 可在 **规则配置 → 聊天维护** 使用 **彻底删除旧配置**，随后重新绑定条目和新 HTML。该操作会清除当前聊天的 LoreState 状态/快照/绑定，重要数据先备份。详见 [作者入门](作者入门.md)。

合法 v2 模板从 0.11.0～0.12.2 升级到 0.12.3 不需要重制；0.10.6 或更早旧模板需要重制 v2 外观。

当前自动化不等于真实模型、真实 SillyTavern、手机键盘和长期视觉验收。发布边界见 [0.12.3 发布说明](发布材料/0.12.3-配置重置与多协议API.md)。
