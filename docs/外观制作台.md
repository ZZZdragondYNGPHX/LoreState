# 外观制作台 · 0.11.1 起（当前 0.12.1）

外观制作台用于从风格描述生成 Template API v2 HTML，或基于当前 HTML 继续改稿。模型结果只进入草稿；必须通过本地安全/字段校验并由用户显式应用，才会改变当前外观。

## 0.12.1 首次使用顺序

首次尚未保存 HTML 时，按下面顺序最稳：

1. 打开 **LoreState → 设置**，选择准备使用的世界书与状态栏模块条目。
2. 点击 **确认绑定状态栏条目**。
3. 打开 **API 预设**，保存用于外观生成的模型来源、API 绑定和请求策略。API 绑定也可以提前保存。
4. 进入 **外观制作**，点击“描述风格 / AI 改稿”。
5. 选择从零生成或基于当前 HTML 改稿，填写布局、配色、展示内容与移动端要求。
6. 点击生成 HTML 草稿；草稿通过校验后进入预览。
7. 需要时继续改稿或手动编辑源码。
8. 确认预览后应用草稿；首次启用仍需回设置点击 **保存 HTML 并启用本聊天**。

`0.12.1` 修复了首次设置时刷新世界书/切换页签导致条目选择丢失的问题。确认绑定会把准备使用的世界书与条目保存进脚本配置，但**不会**启用聊天、修改状态、改变世界书活动规则或自动应用 HTML。

如果已确认的原条目后来被删除，选择会留空并提示重新选择，不会静默改用世界书第一条。

## 生成请求会发送什么

外观生成复用 API 页中已经保存的模型连接、采样、尝试次数、总超时和流式设置，但使用**独立的 HTML 制作任务**。

自动发送的内容只包括：

- 当前 DataSchema / 模块字段结构；
- 你的风格描述；
- 改稿时的当前 HTML。

不会自动附带聊天正文、真实状态值、整段世界书原文或 API 密钥。你自己写进风格描述或 HTML 的文字仍会发送给所选服务，请自行检查敏感内容。

外观请求不使用状态更新任务的 prompt，也不把“当前/指定酒馆预设”的角色卡/聊天历史自动混入制作任务。

## 草稿、预设与当前外观

- **生成 HTML 草稿**：只改内存中的草稿，不直接生效。
- **应用 HTML 草稿**：把通过校验的草稿设为当前随卡外观，但不覆盖命名预设。
- **另存为新预设 / 覆盖所选预设**：只保存预设，不自动切换当前外观。
- **载入所选预设到草稿**：只进入编辑状态。
- **应用所选预设**：明确切换当前外观。

同一角色卡的聊天继续共用随卡外观；当前没有聊天级独立皮肤。

风格要求、未保存草稿和最近一次草稿撤回主要属于当前脚本运行内存；脚本重载或切换角色卡后可能丢失。需要长期保留的外观请保存为命名预设。

## 请求生命周期

请求期间如果发生下面任一变化，迟到结果不会覆盖新状态：

- 切换聊天/角色卡；
- 改变条目绑定或 DataSchema；
- 更换 API 配置；
- 改变当前草稿；
- 主动取消请求。

正文生成、状态更新任务与外观制作互斥，避免把处理中状态拿来生成另一份外观。

## Template API v2 边界

外观仍受 [Template API v2](HTML模板适配指南.md) 的同一套限制：

- 文档根使用 `data-lore-template="2"`；
- 公共字段用 `data-lore-shared`；
- 实体模块用 `data-lore-each`，区域内用 `data-lore-field`；
- 支持 count / empty / active / cold / all / 精确 ID / limit；
- 0.11.1 起支持受控的字段条件显隐和字段值 → class 映射；
- 不执行模型生成的 JavaScript，不开放网络资源、iframe、表单、远程图片/字体或任意属性绑定；
- 状态值只作为文字填充，不执行其中的 HTML。

已有合法 v2 模板从 0.11.0 / 0.11.1 / 0.12.0 升级到 0.12.1 不需要重制。0.10.6 或更早的旧模板原文保留，但需要制作 v2 HTML 才能在当前展示层运行。

## 与状态数据的关系

外观制作不会修改：

- XML v3 状态协议；
- 模块条目定义的 DataSchema；
- full/delta 合并；
- 聊天快照、回档与冷热档；
- EJS 只读桥接状态。

换皮肤只是改变展示。真正增删/改名模块或字段属于 schema 变化，应在独立测试配置和新聊天中验证。

## 校验与验收边界

0.12.1 的最终 bundle 回归覆盖了非第一条目的首次绑定、刷新、双向切页、配置序列化恢复、首次 HTML 生成以及原条目删除；发布记录中还包含 Template API、外观与 EJS 的模拟宿主回归。

这些自动化不等于真实 SillyTavern、实际模型、手机键盘和长期人工视觉验收。完整 0.12.1 证据见 [发布说明](发布材料/0.12.1-条目绑定修复.md)。
