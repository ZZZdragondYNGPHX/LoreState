# 角色卡导出检查 · 0.13.0

## 范围与结论

基底：`main / b534d3efa9b04455d0156a37e725f919e17543a7`。首次实现基于 `817b4bf`，随后快进合入远端文档整理。本次为导出功能边界的完整检查，不宣称完成整个仓库的通用代码审查。

检查覆盖：作者配置写入、规则来源、外观与预设、模型配置、聊天存档、脚本产物和导出开关、导入后读取、可选扩展依赖。发现 3 项遗漏与 1 项导出保护不足，均已在授权范围修复。

## 发现与修改

| 编号 | 级别 | 触发与原影响 | 修改与验证 |
| --- | --- | --- | --- |
| E1 | P1 | 模块规则只保存在外部世界书，脚本只记本机 book/uid；接收方缺少原世界书时无法生成状态提示 | `card-config.js` 保存完整规则副本；`runtime.js` 在绑定/启用及导出准备中捕获，缺失世界书时使用副本。Node 与模拟宿主覆盖；已有世界书删除条目仍报错 |
| E2 | P2 | 本轮最初实现将自定义核对规则放在聊天绑定，单独导出角色卡会遗漏 | 改为脚本数据 `reviewInstructions`；两种更新模式、手动重算、提示预览读取同一份规则；JSON 往返/新聊天测试 |
| E3 | P2 | 更新方式、自动更新、流式、重试和超时只有聊天值；新环境不能继承作者选择的行为 | 新增 `updateDefaults` 白名单，只保存 5 个可移植字段；已配置聊天优先使用原绑定；导入额外模型模式仍要求用户配置自己的连接 |
| E4 | P2 | 产物默认开启数据导出，但用户关闭此开关后 LoreState 没有准备检查入口，可能导出空脚本配置 | 新增“检查并准备角色卡导出”，只开启当前角色脚本的数据/按钮导出，保留其他脚本及未知数据；刷新状态过滤正则 |

结构决定：Local Fix；没有重写存储系统或迁移历史聊天。未因导出检查改写其他角色世界书、个人 API、历史标签或聊天进度。

## 已有功能逐项核对

| 功能 | 结果 / 保存位置 |
| --- | --- |
| 作者默认初始档案与字段约束 | 原先已随卡：`authorPolicy`。补入新环境往返测试及导出准备校验；当前聊天专用 `policy` 保持聊天作用域 |
| DataSchema 与模块定义 | schema 在脚本数据；规则正文现有随卡副本；不能只带 HTML 推导字段 |
| 当前外观与命名预设 | `html`、`presets`、`activePresetId` 均在脚本数据，保存操作保留这些字段 |
| HTML 制作草稿与撤回 | 未应用内容为编辑器内存，属于未保存编辑；界面要求先保存，不暗中替换当前外观 |
| 状态与冷热实体、活动事件、删除编号 | 都在聊天状态及历史消息；随聊天备份，不混入作者初始档案 |
| 快照、读取凭据、回档与撤销 | 聊天命名空间，保持去重正文和恢复能力；不随角色卡分享玩家进度 |
| API 密钥、端点、请求头、模型、思考程度 | 本地全局 API 预设，未复制进脚本数据或产物；私人内置预设文件构建时隔离 |
| 状态模型绑定、当前/指定酒馆预设 | 本地聊天配置；接收方重新选择，避免携带无效的本机 ID 或借用作者账户 |
| 状态块与核对摘要过滤 | 角色局部正则；导出准备和普通生成前更新自己的两条过滤规则 |
| 脚本加载与按钮 | 角色脚本及 `export_with`；固定版本 loader 引用 `@0.13.0/artifact/bundle.js` |
| 脚本/正则总体启用状态 | 接收方的宿主设置，需接收方启用；脚本启用不代表扩展已安装 |
| EJS 桥接 | 代码随 bundle；ST-Prompt-Template 是可选外部依赖，动态世界书条目仍由酒馆导出规则决定 |
| 其他剧情世界书与附加世界书 | 不属于所选 LoreState 规则副本；仍需作者通过酒馆携带对应内容，未把所有外部世界书复制进脚本 |
| 日志、API 原始输出诊断、界面展开状态 | 临时 UI 内存，切聊天清理；不是随卡配置 |
