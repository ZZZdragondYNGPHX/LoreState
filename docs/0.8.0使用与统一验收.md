# 0.8.0 试用版：使用与统一验收

本版包含 0.7.1 的生成失败中止，并加入同层续写拦截、快照正文去重、作者初始档案、文字字段约束和冷档当轮读取凭据。实机测试由用户统一进行；以下项目尚不代表已通过真实酒馆验收。

[0.8.0 远程脚本组件](../prototype/dist/v0.8.0/lorestate-script.json) · [脚本正文 bundle.js](../artifact/bundle.js) · [自动验证记录](../prototype/verification.md)

## 更新与数据边界

先导出测试卡和聊天备份。更新已有脚本时，用本版 bundle.js 全文替换原脚本的 content，保留脚本 ID、data、按钮及导出设置；不要同时启用旧版和新版。远程入口固定 prototype-v0.8.0；Git 分发不代表 CDN 或真实宿主验收通过。当前主线只生成远程入口，离线 JSON 不再作为新交付。

0.7.x 的状态标签仍可读取。首次刷新会把旧完整快照转成去重存档，保留各楼层、分支、错误记录与历史版本。新存档和 read 凭据不能供 0.7.x 正确解释；回退需恢复升级前的聊天备份并使用旧脚本，仅切回代码不构成数据回退。

快照、聊天自己的作者配置及读取凭据都在聊天变量中。脚本只保存未来新聊天的默认配置。角色卡导出不能替代聊天备份；导出再导入的宿主行为需按下表实测。

## 作者初始档案和文字约束

入口：魔法棒 → LoreState → 设置 → 初始档案与字段约束。先保存 HTML，确定栏目，再填写可选配置。下面例子使用公共栏目 `地点、时间`，实体栏目 `状态`：

```html
<section><h3>地点</h3><p data-lore-field="地点"></p><h3>时间</h3><p data-lore-field="时间"></p></section>
<article data-lore-entity><h3 data-lore-name></h3><p data-lore-field="状态"></p></article>
```

初始档案：

```xml
<LoreState version="3" mode="full">
  <Shared><地点>港口</地点><时间>第三天清晨</时间></Shared>
  <Entity id="P1" name="访客" identity="约定来访者" mode="full" presence="cold">
    <状态>等待</状态>
  </Entity>
</LoreState>
```

字段规则：

```json
{
  "shared": {
    "地点": {"required": true},
    "时间": {"noRemove": true}
  },
  "entity": {
    "状态": {"enum": ["等待", "完成", "未知"]}
  }
}
```

`required` 表示必填；`noRemove` 禁止移除已有内容；`enum` 要求完整栏目文字等于某个允许值，不是关键词匹配。枚举最多 32 项，每项最多 200 字符；需要未知值时，将“未知”列入枚举。实体规则作用于所有实体，不按类别分叉。程序不会把非法输出猜改成合法值，任一错误导致整轮不提交。

点击“预览作者配置”，确认解析后的初值。“保存为新聊天默认配置”只影响后续新聊天；“应用到尚未开始的本聊天”仅允许尚无参与更新的 AI 楼层、快照或回档的聊天。已有聊天不能借此重解释历史。

留空初始档案时保持首轮 full；填写后初值先于首轮生效，首轮用 delta。初值的事实来源楼层为未知，不伪装成模型确认。没有明确依据的事实写“未知”。新聊天默认值冻结为聊天自己的配置，之后修改脚本默认值不会改变它。

## 冷档当轮更新

输入明确提及 `P1` 或唯一名称“访客”，或通过有限一跳关联，可完整取回资料。只有最终提示中完整保留的冷档才列入“当轮可更新的冷档编号”。索引、被预算撤下或关联超限的实体不算已读。

模型需原样复制提示中 LoreState 外层的 `read="…"`。本地凭据对应完整前态、配置及加载编号，回放时逐项核对。它不是模型自行声明“已读”的开关，也不证明模型理解了资料。凭据有效且编号在清单内，允许同轮修改冷档，不会自动转热；未加载者仍先空 delta 唤醒、下一轮更新。

旧的无 read 标签仍可回放，但不能直接修改冷档。历史状态或配置改变后，后续凭据可能失效；需核对历史、重新生成受影响回复，或用正常快照回档。不要删除凭据属性绕过检查，丢失凭据不能凭空补造。仅编辑不影响更新前状态的叙事文字不一定导致失效。

## 存储与续写

诊断修复页显示快照数量、共享正文数量和存档 MiB；超过 20 MiB 提示分段聊天。历史版本全部保留，相同状态和配置正文只存一次。资料持续变化仍会增长；没有自动删除历史、语义压缩或增量检查点引擎，历史变化仍会触发全量回放。

“继续生成”同一回复现在明确中止，请发新一轮或重抽。本版没有实现同层续写合并。提示准备、读取凭据保存失败会中止生成；宿主停止接口失效时，界面明确要求手动停止。

## 统一实机测试清单

使用独立测试卡与聊天，分别测试流式和非流式，记录实际 SillyTavern / 酒馆助手版本。测试前备份聊天。

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 旧聊天升级 | 更新脚本并重新读取 | 原状态、旧快照与分支保留，显示去重容量 |
| 初值预览 | 填写上面配置并预览 | 港口、时间、访客等待可见；尚未写入 |
| 初值应用 | 空聊天应用后开始首轮 | 用 delta 接续初值，不重建 full |
| 约束拒绝 | 手动把更新改成删除地点或状态“非法值” | 整轮失败，其他同时修改也不提交 |
| 冷档召回 | 输入“与 P1 见面，把状态记为完成” | 提示完整加载 P1，有效 read 允许同轮更新 |
| 未读保护 | 无完整召回时手动增加冷档栏目修改 | 拒绝，需空唤醒或重新生成并读取 |
| 历史编辑 | 改前面一轮事实并重新校验 | 受影响的后续凭据失效，不套用错误前态 |
| 重抽、删尾 | 重抽刚才一轮，再删最后 AI 层 | 重抽用更新前状态；删尾回退，旧快照仍可选 |
| 回档 | 恢复旧正常快照，再发一轮 | 正文保留、状态回档，新回复接续 |
| 配置隔离 | 修改默认初值，打开新旧聊天 | 新聊天用新默认，旧聊天配置不变 |
| 同层续写 | 点击继续生成 | 中止，不追加第二个状态块 |
| 提示失败 | 测试卡临时使关联失效或规则超预算后生成 | 中止有效模型请求；恢复配置后能继续 |
| 持久化 | 刷新、重开、导出再导入聊天 | 初值、快照、凭据保留，能重新回放 |
| 长聊天 | 连续空 delta，再连续更新事实 | 不变正文去重，变化数据正常增长，耗时可接受 |

有、无初始档案各跑一遍正常生成；中止还须检查宿主停止按钮、输入框恢复及是否实际发出模型请求。完成后据实记录真实宿主与用户验收结论。
