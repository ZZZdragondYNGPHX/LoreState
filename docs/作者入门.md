# 作者入门 · LoreState 0.13.0

LoreState 记录“这一轮之后仍然成立”的事实，例如地点、人物伤势与目标、物品持有者、国家政局、未完成事件。正文仍由原叙事模型生成；LoreState 只维护一份可回放、可增量更新的文字状态。

当前固定稳定版是 **`0.13.1`**。正常使用固定版；`main` 只用于跟随开发。

0.13.0 支持 [更新前核对、自定义规则与随卡导出准备](更新核对与随卡导出.md)。作者初始档案和字段约束应“保存为新聊天默认配置”；分享前点击“检查并准备角色卡导出”。

## 先理解三件事

| 材料 | 负责什么 |
| --- | --- |
| 角色设定/世界观 | 人物、世界、叙事风格和剧情规则 |
| `【LoreState模块 v1】` 条目 | 定义 DataSchema：保存哪些公共栏目和模块栏目、什么时候更新 |
| Template API v2 HTML | 只决定状态怎么显示，不决定存什么 |

**DataSchema 来自模块条目，不从 HTML 反推。** HTML 可以只展示部分字段，这不会删除状态中的字段。

## 第一次配置

1. 导入 [0.13.0 固定远程组件](../prototype/dist/0.13.0/lorestate-script.json)，只启用一份 LoreState。
2. 在角色/聊天世界书中新建模块条目。可以直接从 [module-example.txt](../prototype/module-example.txt) 开始。
3. 打开 **魔法棒 → LoreState → 规则配置**，选择世界书与状态栏条目。
4. 点击 **确认绑定状态栏条目**。0.12.1 起该绑定会在刷新和切页后保持，不再默认改用第一条。
5. 打开 **外观制作**。可复用模型连接生成/修改 HTML 草稿，也可粘贴 [紧凑日志](../prototype/module-example.html) 或 [旅途档案 HUD](../prototype/example.html)。
6. 预览并应用外观，随后点击 **保存 HTML 并启用本聊天**。
7. 发一条普通玩家消息。第一次有效状态回复建立完整状态，之后只提交发生变化的栏目。

确认绑定只保存准备使用的世界书和条目，不会提前写状态或修改世界书活动规则。

## 最小模块条目

```text
【LoreState模块 v1】
【通用规则】
只记录正文已经确认的持久事实；猜测、计划和未发生事件不写成当前事实。

【公共栏目】
栏目：地点、时间
明确移动或剧情时间推进时更新。

【模块：人物】
栏目：身体状况、当前目标
受伤或恢复时更新身体状况；明确改变意图时更新当前目标。

【模块：物品】
栏目：持有者、完好状况
交付、拾取、遗失、损坏或修复时更新。
```

更完整的栏目设计、冷热档、事件和结构限制见 [状态栏条目创作指南](状态栏条目创作指南.md)。历史 0.8/0.9 说明已移入 [archive](archive/README.md)，不再作为新卡教程。

## full 与 delta

首次建立状态时需要完整状态；后续只提交发生变化的栏目。没有变化的栏目由 LoreState 继承。

增量粒度是“栏目”，不是栏目内部的文本 diff。若一个栏目的旧值是“左臂受伤，携带钥匙”，归还钥匙后伤势仍存在，则新值仍应包含“左臂受伤”。

作者通常不需要手写 XML；具体 XML 协议、实体 ID 和读取凭据由 LoreState 当轮提示提供。可读示例见 [状态栏条目与连续更新示例](状态栏条目与对话示例.md)。

## HTML

Template API v2 根节点：

```html
<html lang="zh-CN" data-lore-template="2">
```

公共值用 `data-lore-shared`；实体区域先用 `data-lore-each="模块名"`，区域内再用 `data-lore-field`。完整合同见 [HTML 模板适配指南](HTML模板适配指南.md)。

外观只接受受限静态 HTML/CSS，不执行自定义 JavaScript、远程图片/字体或任意网络资源。

## 想换栏目怎么办（0.12.3 起）

只改规则文字、栏目集合不变时，不需要重做状态结构。

如果要**增删、改名公共栏目或模块栏目**，这是 DataSchema 结构变化。0.12.3 起提供明确的重置流程：

1. 先备份重要角色卡与聊天。
2. 打开 **规则配置 → 聊天维护**。
3. 输入 `删除旧配置`。
4. 点击 **彻底删除旧配置**。
5. 重新选择世界书/模块条目并确认绑定。
6. 重新生成或应用与新 DataSchema 匹配的 Template API v2 HTML。
7. 保存 HTML 并重新启用当前聊天。

该操作会删除本脚本配置，以及**当前聊天**的 LoreState 状态、快照、回档、更新绑定和恢复备份；不会删除聊天正文、世界书或全局 API 预设。其他旧聊天不会被批量删除，但在新配置代次下会停用，重新保存启用时会清理旧状态并从新起点继续。

这不是普通“暂停”功能，且不可撤销。完整范围见 [0.12.3 发布说明](发布材料/0.12.3-配置重置与多协议API.md)。

## 升级到 0.13.0

从 `0.12.3` 升级到 `0.13.0` 不需要重建已有 v3 状态、作者档案、快照或合法 Template API v2 外观。升级后建议重新保存状态更新绑定；如果要分享角色卡，再执行一次 **检查并准备角色卡导出**，让自定义核对规则、更新默认值和模块规则副本完整写入随卡配置。

从 `0.11.0`～`0.12.2` 升级时，原有合法 v2 外观、v3 状态和快照同样无需因为版本号本身迁移；`0.10.6` 或更早的旧 HTML 需要重制为 Template API v2。具体边界以 [版本管理](版本管理.md) 为准。

## 可选能力

- [额外模型与 API 预设](额外模型与API预设.md)：独立状态模型、多协议连接、重试、取消、手动重算与撤销。
- [外观制作台](外观制作台.md)：用模型生成/修改 v2 HTML 草稿。
- [EJS / 动态世界书](EJS动态世界书.md)：可选接入 ST-Prompt-Template，只读读取冻结快照并按区间/阶段输出世界书内容。
- [隐藏助手兼容与更新](隐藏助手兼容与更新.md)：隐藏旧正文时保持本地状态回放连续。

## 发布角色卡之前

至少在独立测试聊天中检查：固定版本、非第一条世界书绑定、full → delta、跨模块更新、刷新/切聊天、回档、HTML 显示、过滤规则，以及 0.13.0 的更新前核对。分享前先在 **规则配置 → 角色卡导出** 执行 **检查并准备角色卡导出**，再用酒馆导出并在独立副本重新导入；使用额外模型/EJS 时再测试对应路径。

自动化与模拟宿主通过不等于真实 SillyTavern、真实模型、手机和长期游玩已经验收。完整清单见 [常见问题与试卡清单](常见问题与试卡清单.md)。
