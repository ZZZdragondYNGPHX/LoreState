# 从纯文字卡开始

LoreState 适合记录“这一轮以后仍然成立”的信息：当前地点、人物持有的物品、国家关系变化、欠款、伤势、约定等。你仍然写普通角色设定和故事；额外准备一条状态维护说明，以及一份用于显示状态的 HTML。

这里的“纯文字”指状态内容是普通文字。运行 LoreState 仍需要酒馆助手脚本；它不是完全不依赖扩展的便携文字卡，也不提供 MVU 数值计算或自动战斗结算。

## 三样东西各自负责什么

| 材料 | 作者写什么 | 谁使用 |
| --- | --- | --- |
| 原有角色设定和世界观 | 人物是谁、世界如何运作、故事怎么写 | 叙事模型 |
| 状态栏条目 | 记录哪些栏目、什么情况下改、什么保持未知 | LoreState 读取后加入生成提示 |
| HTML 模板 | 哪些文字显示在哪里、颜色与排版 | 脚本解析栏目并显示状态 |

**栏目名单由 HTML 绑定推导。** 只在条目里写“增加好感度”，并不会自动增加可保存的栏目。条目与 HTML 必须使用相同的栏目名。

最小方案只用常驻“地点、时间”。需要持续记住多个人或事物时，再加入通用实体栏目。建议从示例中的“概况、当前状态”开始：人物、国家、物品和事件都能填写这两项。

## 第一次试做

1. 在新测试聊天中使用 0.7.0 脚本，只启用一个版本。离线脚本包含代码；远程脚本需要访问固定版本的 CDN。项目目标环境为 SillyTavern 1.18.0 / 酒馆助手 4.9.5，本版尚未真实宿主验收。
2. 在角色或聊天绑定的世界书里，新建一条“LoreState · 状态维护规则”，粘贴 [示例条目](状态栏条目与对话示例.md)。只复制指定的 `text` 代码块，不复制整个教程。
3. 这条规则建议作为脚本读取的来源，关闭其普通世界书自动注入，避免同一规则出现两遍。当前脚本按保存的世界书和条目 UID 直接读取内容，不依赖关键词触发。其他叙事条目保留自己的启用方式。
4. 从魔法棒打开 **LoreState**，进入设置，选择该世界书和规则条目。
5. 点击 **生成并复制 HTML 制作提示词**，交给网页 AI 制作模板；也可以直接采用 [配套模板](HTML模板适配指南.md)。粘贴完整 HTML，先预览，再点击 **保存 HTML 并启用本聊天**。
6. 确认本卡局部正则已启用。保存配置会安装显示过滤与提示词过滤两条规则；它们隐藏更新标签的副本，保留聊天原文用于回放。
7. 发一条普通玩家消息，检查第一次参与状态记录的 AI 回复是否输出完整状态。以后只输出变化。使用 **查看下一轮状态提示** 检查规则、栏目和当前资料是否一致。

先配置再开始试卡，不要把中途已有几十轮正文的聊天当作全新初始化样本。默认流程从后续 AI 回复建立状态，首条开场白不应成为唯一的初始化来源；如果你希望开场事实被记录，请在角色设定或状态规则中明确初值，再通过第一轮玩家发言进入正常生成。

## 作者需要写 XML 吗

日常创作主要写自然语言规则，脚本会提供 XML 协议说明，模型按协议输出。你读懂几个例子，就能判断“第一次完整、以后增量”是否正常，不必手写每轮状态。

不要要求模型每轮重写整块 HTML，也不要把它已有的 `<LoreState>` 协议替换成自制 `<状态栏>`。同一回复的正文和状态由同一次生成产生，脚本不会额外调用模型修复或补读。

## 给读者之前

配置、模板和预设保存在脚本数据中；确认脚本的数据随卡导出选项开启，并在新的测试环境复查。游玩中的状态与历史快照属于聊天，角色卡导出不等于聊天备份。

完整试卡流程见 [试卡清单](常见问题与试卡清单.md)。离线测试通过后仍要检查真实模型能否遵守你的具体规则。
