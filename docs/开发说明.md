# 开发入口与目录约定

当前唯一活动维护线为 `prototype/` 的 Tavern Helper 脚本；`main` 是唯一长期开发分支。根目录原生扩展保留为旧实现。版本与分支规则以[版本管理](版本管理.md)和根目录 `AGENTS.md` 为准。

| 路径 | 职责 |
| --- | --- |
| `prototype/core.js` | 标签解析、合并、状态回放与提示词 |
| `prototype/modules.js` | 模块栏目与按需规则 |
| `prototype/runtime.js` | 宿主接入、管理器与事件 |
| `prototype/api-profiles.js`、`api-panel.js`、`extra-update.js` | 本地 API 预设、聊天绑定界面与独立更新校验；请求生命周期由 runtime 管理 |
| `prototype/snapshots.js`、`snapshot-store.js` | 快照、回档、历史身份和读取凭据存储 |
| `prototype/template.js`、`state-frame.js` | 模板校验、安全绑定与状态窗口 |
| `scripts/build-prototype.mjs` | 脚本构建与按 ref 分发 |
| `scripts/check.mjs` | 语法、版本管理和远程入口守卫 |
| `artifact/bundle.js` | `main` 的生成运行代码 |
| `prototype/dist/main/` | 当前 `main` 远程组件与收据 |
| `prototype/dist/<version>/` | 发布 tag 对应的固定版本入口 |
| `docs/` | 当前作者、开发、试卡文档；发布材料在 `docs/发布材料/`，旧记录在 `docs/archive/` |
| `tests/` | Tavern Helper 脚本与旧扩展的自动回归 |
| `src/`、`index.js`、`manifest.json` | 旧原生扩展；其中 `0.2.1` 不代表 Tavern Helper 版本 |

`examples/` 和 WishNote 分支已退休，不是可恢复的开发入口。无版本根入口 `prototype/dist/lorestate-script*.json` / `prototype/dist/receipt.json` 也已退休；活动入口只能在 `prototype/dist/main/` 或明确版本目录中。

## 检查与构建

Node.js 22+。

开发版构建：

```sh
npm run build
npm run check
npm test
```

`npm run build` 输出：

- `artifact/bundle.js`
- `prototype/dist/main/lorestate-script.json`
- `prototype/dist/main/receipt.json`

`main` loader 必须且只能引用 `@main/artifact/bundle.js`。构建产物由脚本生成，不手工修改。

准备新的固定版本时，在创建 tag **之前**运行（以下版本号仅作下一版示例）：

```sh
npm run build -- 0.10.7
npm run check
npm test
```

这会生成对应的 `prototype/dist/<version>/`，其中 loader 和 receipt 都必须固定到同名版本。提交这些生成物后，再让同名 tag 指向同一提交；tag 创建后不得移动。

CI 在语义版本 tag 上会校验对应版本目录；如果有人创建语义版本名 branch，`npm run check` 会直接失败。版本号只属于 tag，不属于 branch。

涉及模板、UI 或宿主行为时再运行：

```sh
node scripts/test-browser.mjs
```

浏览器检查默认使用 Windows Edge；可通过 `LORESTATE_BROWSER` 指定浏览器可执行文件。它测试模板和最终 `artifact/bundle.js` 的模拟宿主行为，不是实际酒馆验收。

## Template API v2 展示边界

`0.11.0` 将模板与存储 schema 解耦，完整作者合同见 [HTML 模板适配指南](HTML模板适配指南.md)，固定发布证据见 [0.11.0 发布说明](发布材料/0.11.0-Template-API-v2.md)。

- `moduleShape(parseModules(entry.content))` 独立产生 DataSchema；保存配置仍保留 `shared/entity/modules` 与 schema 变更保护。
- `inspectTemplateV2` / `validateTemplateV2` 只检查安全、绑定与字段引用，返回 TemplatePlan，不再导出旧 templateSchema。
- `renderTemplateV2(html, state, schema)` 只读消费状态；部分字段、重复字段、分类区域、active/cold/all、精确 ID、count/empty/limit 共用一条规则。
- 预览、启用、预设另存/覆盖/应用、聊天 paint 和展开窗口全部走 v2；旧模板保留文本，局部错误态不阻断状态回放，也不反复重建。
- 仅移除正文尾部硬编码冷档列表；管理器档案、读取凭据、XML v3、状态更新和回档保持原样。
- HTML/CSS 检查使用静态白名单、词法门和原生 CSSOM；不添加依赖，不开放 iframe 脚本或网络权限。

两个模板 `prototype/example.html` 与 `prototype/module-example.html` 均配套原有 `prototype/module-example.txt`，示范同一 DataSchema 的不同外观。模板浏览器测试会校验示例、作者文档与 authorPrompt 生成的 HTML，并检查窄屏、长文字和字体放大。

必需检查仍为 build → check → test → test-browser。最后一项检查最终 bundle 的模拟宿主，不代替真实酒馆、实际模型和人工视觉验收。已有固定版本目录/tag 不随开发候选变动。

## 固定版本问题的复现

用户报告某个版本问题时，先确认实际 ref，再读取该 ref 的源文件和 `artifact/bundle.js`。不要从 `main` 推断固定版本。

推荐顺序：

1. 记录用户实际 import 的 ref；
2. 读取目标 ref 的 `prototype/` 源码与相关文件 blob SHA；
3. 与 `main` 比较内容；
4. 需要临时日志时，从精确 commit 建 `debug/<version>-<slug>`；
5. 临时诊断不得进入 `main` 活动 loader；
6. 根因修复落在维护源并增加测试；
7. 重新构建、合回 `main`，删除 debug 分支；
8. 如需稳定交付，发布新的 patch tag。

历史 `0.10.3` RC 已从误建的版本号 branch 原样固化为同名兼容 tag，原 branch 已删除；`0.10.4` 与 `0.10.5` 已按完整固定版本目录规范发布，当前固定安装使用 `0.11.0` 标签。

## 隐藏楼层回归约定

本地状态历史包含隐藏的 AI 消息；隐藏只是上下文可见性。回放、诊断和快照应保持一致。历史身份忽略隐藏位，但保留楼层、角色、回复分支和原文；旧回档前缀的隐藏位可归一化比较。真正的原文变动仍受校验。

相关回归在 `tests/hidden-history.test.mjs` 与 `tests/runtime-browser.js`。不得把私人聊天作为仓库测试夹具；使用合成数据覆盖同类条件。
