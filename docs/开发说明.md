# 开发入口与目录约定

当前唯一活动维护线为 `prototype/` 的 Tavern Helper 脚本；`main` 是唯一长期开发分支。当前固定稳定版为不可移动标签 **`0.12.2`**。仓库根目录的原生扩展保留为旧实现，不代表当前 Tavern Helper 版本。

版本与分支规则以[版本管理](版本管理.md)和根目录 `AGENTS.md` 为准。

## 主要目录

| 路径 | 职责 |
| --- | --- |
| `prototype/core.js` | 标签解析、合并、状态回放与提示词 |
| `prototype/modules.js` | 模块条目、DataSchema 与按需规则 |
| `prototype/runtime.js` | 宿主接入、控制中心、生成生命周期 |
| `prototype/ejs-bridge.js` | 可选 Prompt Template 只读快照、路径/区间/阶段 API |
| `prototype/api-profiles.js`、`api-panel.js`、`extra-update.js` | API 预设、额外模型更新、手动重算 |
| `prototype/snapshots.js`、`snapshot-store.js` | 快照、回档、历史身份、读取凭据 |
| `prototype/appearance-authoring.js`、`appearance-panel.js` | 外观生成请求、草稿与工作区 |
| `prototype/template-display.js` | v2 条件显隐与安全 class 映射 |
| `prototype/template.js`、`state-frame.js` | Template API v2 校验、渲染与状态窗口 |
| `scripts/build-prototype.mjs` | main / 固定版本构建与远程入口生成 |
| `scripts/check.mjs` | 语法、版本、入口和生成物守卫 |
| `artifact/bundle.js` | `main` 的生成运行代码，不手工维护 |
| `prototype/dist/main/` | 当前 main 远程组件与收据 |
| `prototype/dist/<version>/` | 对应不可移动 tag 的固定版本入口 |
| `docs/` | 当前作者、开发、试卡文档 |
| `docs/发布材料/` | 当前发布材料与各版本发布证据 |
| `tests/` | Node / 浏览器 / EJS 等回归 |
| `src/`、`index.js`、`manifest.json` | 历史原生扩展；其中 `0.2.1` 不是当前脚本版本 |

`examples/`、WishNote 旧入口和无版本 `prototype/dist/` 根组件均已退休，不作为当前开发/安装入口。

## 当前构建

要求 Node.js 22+。

开发版：

```sh
npm run build
npm run check
npm test
```

`npm run build` 生成：

- `artifact/bundle.js`
- `prototype/dist/main/lorestate-script.json`
- `prototype/dist/main/receipt.json`

main loader 必须只引用 `@main/artifact/bundle.js`。

涉及模板、控制中心、宿主事件或 EJS 时还应运行：

```sh
node scripts/test-browser.mjs
```

EJS 相关可额外运行：

```sh
node scripts/test-ejs.mjs
```

这些浏览器/上游 smoke 是模拟与版本化源码验证，不等于真实 SillyTavern/模型验收。

## 准备新的固定版本

当前 `0.12.2` 已发布。下一 patch 版本示例使用 `0.12.3`：

```sh
npm run build -- 0.12.3
npm run check
npm test
node scripts/test-browser.mjs
```

构建会额外生成 `prototype/dist/0.12.3/`；其中 loader/receipt 必须固定到 `@0.12.3`，不能引用 `@main`。提交维护源和生成物并完成检查后，再让同名 tag 指向该提交。

语义版本号只属于 tag，不属于 branch。已经发布的 tag 永远不移动。

## Template API v2

`0.11.0` 起模板和 DataSchema 解耦：模块条目通过 `moduleShape(parseModules(...))` 产生状态 schema；HTML 只生成只读 TemplatePlan 并消费状态。

当前 v2 支持：

- `data-lore-shared` 公共值；
- `data-lore-each` 分类重复；
- `data-lore-field` 模块字段；
- active/cold/all、select-id、limit、count、empty；
- 0.11.1 起的条件显隐与字段值 → class 映射。

预览、启用、命名预设、聊天渲染和展开窗口必须走同一套 v2 校验链。旧模板错误只能阻止 HUD，不能破坏状态回放。

完整作者合同见 [HTML 模板适配指南](HTML模板适配指南.md)。

## 0.12.1 首次条目绑定

首次尚未保存 HTML 时，用户需要先在设置选择世界书和模块条目，并点击 **确认绑定状态栏条目**。运行时必须：

- 保存明确选中的世界书/条目，而不是默认第一条；
- 刷新列表和设置/外观页切换后恢复该选择；
- 原条目消失时留空并提示，不自动误绑；
- 只确认绑定，不提前启用聊天或改状态；
- 首次外观生成从已确认的正确条目读取 DataSchema；
- 异步读取丢弃过时结果，切聊天清理临时选择。

固定发布证据见 [0.12.1 条目绑定修复](发布材料/0.12.1-条目绑定修复.md)。

## 外观制作边界

外观制作复用已经保存的 API 连接、采样、流式、重试和超时，但使用独立 HTML 任务：

- 不复用状态更新 prompt；
- 不自动发送聊天正文、真实状态或整段世界书；
- 结果先进入草稿；
- 只有显式应用才改变当前外观；
- 请求生命周期受聊天、schema、API 和草稿变化保护；
- 仍受 Template API v2 的 sandbox/CSP/静态白名单约束。

维护说明见 [外观制作台](外观制作台.md)。

## EJS 只读桥接边界

`prototype/ejs-bridge.js` 不导入 EJS 引擎；它通过 Prompt Template 的 prepare 事件暴露当前可靠 LoreState 快照和 helper。

核心约束：

- 状态读取仍以现有回放结果为唯一事实源；
- 普通生成、swipe/regenerate/continue 前态和旧楼层渲染分别处理；
- 历史缺口、不可追踪生成边界、聊天切换等返回空态；
- 快照深拷贝并深冻结；
- 不提供 set/patch/commit；
- 不发放冷档写入凭据；
- runtime 关闭/替换时清理监听和临时边界。

`tests/ejs-bridge.test.mjs` 覆盖纯 API；浏览器回归覆盖最终 bundle 的宿主时序；`scripts/test-ejs.mjs` 只在验证环境执行固定上游 EJS smoke，不打包运行时引擎。

完整合同见 [EJS / 动态世界书](EJS动态世界书.md)。

## 固定版本问题怎么复现

用户报告固定版本问题时：

1. 先记录实际加载的 ref；
2. 读取该 tag 的维护源与 `artifact/bundle.js`；
3. 与当前 main 比较；
4. 需要临时日志时从精确 commit 建 `debug/<version>-<slug>`；
5. 诊断代码不得进入 main 活动 loader；
6. 根因修复落在维护源并补测试；
7. 重建、合回 main，删除临时分支；
8. 需要稳定交付时发布新的 patch tag。

不要移动旧 tag，也不要用“额外 loader + 旧 bundle”长期冒充新版本。

历史 `0.10.3` RC 已固化为同名兼容 tag；`0.10.4` 起采用完整固定版本目录规范。当前固定安装使用 **`0.12.2`**。

## 隐藏楼层回归

隐藏只是模型上下文可见性，不等于从本地状态历史删除。回放、诊断、快照与 EJS 都应继续看到属于当前分支的隐藏 AI 楼层。

真正的原文编辑、删除、回复分支变化仍必须触发历史校验。相关回归见隐藏历史测试与 [隐藏助手兼容与更新](隐藏助手兼容与更新.md)。

## 提交前最低检查

文档/代码范围不同，但涉及运行代码时至少确认：

```sh
npm run build
npm run check
npm test
```

按改动补 `test-browser` / `test-ejs`，再检查生成物与维护源一致、固定 loader ref 正确、Git diff 无意外历史文件改写。
