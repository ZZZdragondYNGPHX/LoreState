# 额外模型更新与 API 预设 · 当前 0.12.2

额外模型更新从 `0.10.0` 起提供，当前固定版 **`0.12.2`** 与 `main` 均包含这一能力。它可以把状态更新交给独立模型，也可以为外观制作台提供模型连接。已有 v3 状态无需转换。

真实服务的模型遵循率、网络兼容和具体供应商参数支持仍需按用户环境验收；自动化与模拟宿主不等于真实 API 已验证。

## 配置 API 预设

1. 打开 **LoreState → 模型连接**。
2. 展开 **管理 API 预设**，填写预设名称、OpenAI 兼容 API 基础地址、密钥和模型名。
3. 模型名可手填，也可点击获取模型列表后选择。
4. 按需设置最大回复 tokens、温度、Top P、Top K、频率惩罚、存在惩罚、流式接收、请求总次数和总超时。
5. 点击保存 API 预设。

地址使用基础地址，例如 `https://example.com/v1`；若填完整 `/chat/completions` 地址，界面会按现有规则规范化。当前独立 API 路径面向 OpenAI 兼容格式，不等同于 Claude/Gemini 原生协议适配器。

API 密钥保存在当前酒馆用户的全局设置中，不写入角色卡、LoreState HTML、聊天状态或请求预览。完整酒馆设置备份仍可能包含密钥。

## 状态更新绑定

在请求内容中选择 **额外模型更新**，再选择：

- 模型来源：跟随酒馆当前 Chat Completion 连接，或绑定独立 API 预设；
- 请求预设：内置预设、当前酒馆预设或指定酒馆预设；
- 自动更新：正文结束后是否自动触发；
- 请求总次数：1～5；
- 总超时：15～600 秒；
- 是否使用兼容流式接收。

点击 **保存状态更新绑定** 后，这些设置随当前聊天的绑定保存。

跟随当前连接时要求是可用的 Chat Completion 路径；如果当前连接属于 Text Completion，应绑定独立 API，而不是静默换服务。

## 三种请求预设

| 预设 | 行为 |
| --- | --- |
| 内置预设 | 使用 LoreState 自己的可选头/尾补充；固定状态任务始终发送 |
| 当前酒馆预设 | 复用当前酒馆预设组装，并加入本轮状态任务 |
| 指定酒馆预设 | 明确选择已有酒馆预设；不存在时拒绝请求，不自动回退 |

指定/当前酒馆预设可能携带其自己的角色/世界书注入，因此最终提示长度取决于所选预设。LoreState 最终仍只接受一个合法状态更新块。

## 更新如何工作

正文模型先正常续写剧情。额外状态模型随后收到：

- 状态规则和 DataSchema；
- 本轮更新前的可靠状态；
- 当前玩家输入；
- 本轮 AI 剧情正文；
- LoreState 输出协议与读取权限。

模型返回唯一状态更新块。只有完整校验成功才写入消息；任何非法栏目、读取权限、协议或写入失败都不会部分提交。

网络失败或输出校验失败可以按设置串行重试；一旦成功立即停止。取消、超时、聊天/配置/分支/消息变化会终止剩余尝试并阻止迟到结果写入。

`0.10.5` 起（包含当前 0.12.2），如果返回了完整 LoreState 块但本地校验失败，后续重试可带上校验原因；道歉、拒答、空响应等没有完整状态块的结果按原任务重试，不把旧纠错提示残留到下一次请求。

## 手动重新更新最新回复

额外模型模式可以在 **更新与恢复** 页点击 **重新更新最新回复状态**：保留正文，从该楼层开始前的可靠状态重新判断，替换该楼层旧状态块，而不是叠加第二块。

已有正确标签也可以重新判断。操作只针对当前聊天末尾 AI 回复；历史批量重算仍不是当前功能。

## 随正文失败后的手动重算 · 0.10.5 起

即使当前使用 **随正文更新**，最新 AI 回复的状态校验失败后，统一在 **更新与恢复** 页点击 **重新计算最新失败回复状态**。上方楼层选择只影响历史查看，不改变更新目标；不再提供第二个重算入口。

它复用已经保存的状态模型来源、重试、超时、取消、读取凭据和撤销逻辑，但**不会**自动把当前绑定切换成额外模型更新。

输入是该楼层之前的可靠状态、本轮玩家输入与剧情正文。成功后替换/补上状态块，正文保持不变。正常回复不会因为这个按钮被自动重算；此前已有历史缺口时，应先处理更早错误。

## 尾部截断状态块 · 0.10.5 起

如果最新回复正文完整，但尾部 LoreState 块被截断，点击 **重新计算最新失败回复状态** 后，会在同一操作区先显示正文与截断尾部的分界预览，此时不请求模型。

只有边界明确时才允许：

- 单一 `<LoreState` 起点；
- 起点前有需要保留的完整正文；
- 到消息末尾没有完整闭合块；
- 没有多个/嵌套/模糊起点。

预览显示“保留正文”和“替换的截断尾部”。点击 **确认边界并重算** 后，只有保留正文进入状态模型；成功结果替换截断尾部。请求失败、取消、超时或写入失败不会先删除旧尾部。

撤销备份保存完整原消息，因此成功修复后仍可以用 **撤销最近一次状态更新** 恢复。

## 同层续写与回档

当前实现支持最新 AI 回复的同层续写整理：完成后只保留一个代表整条回复结果的状态块。续写中途停止或自动更新关闭时，新增正文保留，但状态可能显示缺口，需要完成整理或手动重算。

快照回档之后，新回复与额外模型更新从回档基线继续。回档前保留区的旧回复不允许原地重算/重抽/续写，以避免修改已固定历史。

这些组合已经有模拟宿主回归，但真实酒馆的流式/非流式时序仍应实测。

## 取消与撤销

- **取消状态更新**：取消当前独立请求并停止后续重试。
- **撤销最近一次状态更新**：恢复本聊天最近一次 LoreState 写入前的完整消息。

如果目标消息已经被编辑、切换了回复分支、增加了后续消息或处于不允许覆盖的回档区域，撤销会拒绝覆盖。

## 请求诊断

更新与恢复页会保留当前聊天最近的状态请求诊断，包括请求状态、原始模型返回和本地校验错误；不会保存请求提示到聊天，也不会把密钥写入诊断。切换聊天或主动清除会清空对应内存诊断。

诊断中可能包含模型原始输出，因此分享前仍应检查是否含有角色卡或剧情中的私人内容。

## 内置预设头尾

开发者可在 `prototype/builtin-preset.js` 中维护内置头/尾补充，使用 UTF-8 → 标准 Base64 编码。Base64 只是编码，不是加密；脚本使用者和请求服务仍可看到解码内容。

内置顺序为：头部（非空）→ 固定状态任务 → 本轮剧情 → 尾部（非空）。当前/指定酒馆预设走酒馆助手自己的预设组装，不叠加这两个内置补充。

修改维护源后用 `npm run build` 重建 `artifact/bundle.js` 和 main 组件，不要直接编辑 bundle。

## 同一 API 绑定用于外观制作 · 0.11.1 起

API 预设也可被 [外观制作台](外观制作台.md) 复用。外观请求是独立 HTML 任务，不使用状态更新 prompt，也不会自动发送真实聊天、状态值或整段世界书。

在当前 `0.12.2` 的**首次 HTML 制作**中：

1. API 连接可以提前保存；
2. 但在真正生成外观前，先到规则配置选择世界书和状态栏条目；
3. 点击 **确认绑定状态栏条目**；
4. 再进入外观制作，让任务使用正确的 DataSchema。

这正是 0.12.1 修复的首次绑定流程。

## 当前边界

- 不导入 MVU 运行库，不使用 MVU 补丁协议；
- 不支持任意历史楼层批量重算；
- 独立 API 主要面向 OpenAI 兼容 Chat Completion；
- 状态提示与剧情仍有字符预算，字符上限不等于服务商 token 上限；
- 实际供应商是否支持某个采样参数由服务自己决定；
- 自动化不能替代真实模型遵循率、真实网络和第三方扩展组合测试。

当前稳定安装使用 `0.12.2`。开发实现、宿主源码依据和历史发布证据见 [开发说明](开发说明.md)、[验证记录](../prototype/verification.md) 与各版本发布说明。
