# 额外模型更新与 API 预设

本功能纳入 `0.10.0` 标签及 `main` 远程脚本，已通过自动化与模拟宿主检查，尚未在真实酒馆调用模型验收。发布版内置预设头尾留空。

## 配置

1. 在已启用 LoreState 的聊天中，打开魔法棒 → LoreState → **API 预设**。
2. 填写预设名称、API 地址、密钥和模型名称。地址使用 OpenAI 兼容接口的基础地址，如 `https://example.com/v1`；填写完整 `/chat/completions` 地址会自动去掉这一后缀。第一版不支持 Claude/Gemini 原生接口格式。
3. 模型名称可手动填写，也可点击 **获取模型列表** 后选择；列表请求使用当前输入的地址和密钥，不自动保存预设。展开高级采样参数按需设置，点击 **保存 API 预设**。另存新预设时填写不同名称。
4. 在请求内容中选择 **额外模型更新**，选择请求预设；在模型来源中选择 **绑定 API 预设** 及对应预设，或 **跟随酒馆当前连接**。
5. 设置自动更新、流式接收、请求总次数和总超时，点击 **保存状态更新绑定**。上方的请求设置与聊天绑定会一起保存。

## 提示词与请求参数

| 配置 | 行为 |
| --- | --- |
| 内置预设 | 使用本脚本的预设补充内容，默认留空。固定状态任务仍完整发送 |
| 当前酒馆预设 | 使用当前酒馆预设，同时携带本轮状态任务；不切换正文预设 |
| 指定酒馆预设 | 选择已有酒馆预设供本次请求使用；预设不存在时拒绝请求，不回退 |
| 自动更新 | 默认开启。关闭后正文结束不调用额外模型，由用户点击重新更新 |
| 请求总次数 | 1～5 次，默认 1；串行请求，网络失败或格式校验失败才尝试下一次。成功后立即停止 |
| 总超时 | 15～600 秒，默认 120；覆盖整个更新及全部尝试。取消、超时或聊天/配置变化均终止重试 |
| 兼容流式响应 | 默认关闭；开启后用流式接收完整结果，校验成功前不写入部分状态 |
| 模型来源 | 跟随酒馆当前 Chat Completion 连接，或使用单独绑定的 OpenAI 兼容 API；当前连接为 Text Completion 时需绑定独立 API |
| 最大回复 tokens | 默认 4096；0 表示不发送该参数 |
| 温度、Top P、Top K、频率惩罚、存在惩罚 | 分别配置；留空表示不发送。Top K 为 0 也不发送；具体支持由服务决定 |

指定酒馆预设时，酒馆助手会用该预设的采样参数覆盖对应请求参数；API 预设仍决定独立地址、密钥和模型。使用内置或当前酒馆预设并绑定独立 API 时，采用 API 预设中的采样设置。跟随当前连接时，不使用独立 API 预设的参数。

本轮状态任务完整放在请求输入中，即使指定预设省略聊天历史占位，也不会漏掉 LoreState 输出格式。酒馆预设可以额外带入自身配置的角色或世界书内容，因此这一路径的提示内容与长度取决于所选预设；最终仍只接受唯一合法的 LoreState 状态块。

### 提示词编辑位置

固定任务与可选预设分开维护：

- [builtin-preset.js](../prototype/builtin-preset.js) 的 `BUILTIN_PRESET_HEAD_BASE64` 和 `BUILTIN_PRESET_TAIL_BASE64` 分别存放头部、尾部的编码文本，默认均为空。将原文按 **UTF-8 → 标准 Base64** 编码，再粘贴到反引号内；保留末尾 `=`，允许换行，不使用 Base64URL。只有选择“内置预设”时，在请求组装阶段解码为原文发送。编码损坏或不是有效 UTF-8 时停止请求，不发送乱码。
- Base64 是可逆编码，不是保密加密，没有密钥；脚本使用者与 API 服务仍可看到解码后的提示词。可在本机 PowerShell 编码 UTF-8 文本文件：`[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes([IO.File]::ReadAllText('D:\\提示词.txt', [Text.Encoding]::UTF8)))`。头尾分别编码，修改后运行 `npm run build`。
- 内置预设请求顺序为：头部（system，非空才发送）→ 固定状态任务（system）→ 本轮剧情（user）→ 尾部（system，非空才发送）。`api-profiles.js` 调用 `builtinOrderedPrompts` 组装，与 MVU 的头尾加载思路一致；本项目使用本地 JS 模块在构建时打包，不在请求时下载远程文本。当前/指定酒馆预设走酒馆助手的预设组装，不叠加这两个内置部分。
- [core.js](../prototype/core.js) 的 `preparePrompt` 负责状态规则、栏目和输出格式；[api-profiles.js](../prototype/api-profiles.js) 的 `extraModelRequest` 负责固定任务与请求组装。固定任务在三种预设路径中始终发送。

修改维护源后运行 `npm run build`，由构建更新 `artifact/bundle.js` 和 main 组件；不要直接修改 bundle。用户仍需加载修改后的脚本，未推送的源码不会随远程入口刷新。

预设在当前酒馆用户下共用，更新方式与绑定保存在各自聊天中。编辑预设与状态绑定是两个选择：编辑 B 不会把原本绑定的 A 改成 B；保存对 A 的修改则会影响所有绑定 A 的聊天。删除预设后，原绑定会显示失效并拒绝请求，不自动改用另一个 API。正文模型与正文预设保持原设置。

密钥保存在酒馆用户配置的独立命名空间中，以本地明文设置持久化，不随角色脚本或聊天导出。完整酒馆设置备份仍可能包含密钥。脚本不会把密钥写入自己的诊断报告；第三方扩展与 API 服务的日志不在此保证范围内。

## 更新与重试

开启后，正文模型收到当前只读状态并续写剧情；正文完成后，绑定模型收到状态规则、更新前状态、当前用户输入与本轮剧情，生成唯一的 LoreState 更新块。沿用原来的栏目、full/delta、冷热档和读取凭据校验，只有整轮校验成功才写入消息。

**重新更新最新回复状态**会保留正文，从该轮之前的有效状态重新计算，替换该轮旧更新块，不累加旧结果。已有正确标签也可以重新判断。原文存在未闭合的 LoreState 标签时，需要先修好标签边界，避免误删正文。

**取消状态更新**取消当前请求并终止后续重试。超时遵守上方总超时配置。**撤销最近一次状态更新**恢复本聊天上一次写入前的完整消息。若已新增后续消息、切换回复分支或编辑目标消息，撤销会拒绝覆盖。

请求失败、输出错误或写入失败会显示提示；切换聊天、修改规则、消息、分支或绑定会阻止旧结果写入。刷新页面、重新校验状态及切换聊天不会自动补发模型请求。更新未完成时，应先处理最新回复，避免带着状态缺口继续生成。

切回 **随正文更新** 并保存绑定，即恢复原方式。既有 v3 状态无需转换。

## 当前边界与实机验收

- 只重新更新最新一条 AI 回复，不批量重算历史；前面已有错误时需先修复。
- 支持最新 AI 回复的同层续写：随正文模式要求模型在新增正文末尾给出替代旧块的新状态块，描述整条回复相对本轮开始前的变化；额外模型模式使用整条续写后的正文重新更新。成功整理后只保留一个状态块。
- 续写中途停止或关闭自动更新时，新增正文保留，过时的旧状态块会移除并显示状态缺口；额外模型模式可点击“重新更新最新回复状态”补齐。随正文模式缺少合法新块时可重抽整条回复，或切换额外模型补算。原文被宿主处理或其他扩展改写、分支发生变化时拒绝自动合并，需先恢复原分支；未完成的整理记录会保存，重载后可继续整理，但不会自动补发模型请求。
- 支持快照回档后的额外模型更新：新回复、重新更新、撤销最近一次更新和新回复的同层续写都从回档基线计算。回档只恢复状态，旧正文仍在剧情上下文中；回档时已保留的旧回复不可直接重算、重抽或续写，需先发送新一轮。任意旧楼层批量重算与后续历史连锁修复仍未实现。
- 上述续写与回档组合已通过模拟宿主检查，真实酒馆流式/非流式时序、模型遵循率及其他扩展兼容仍待实机验收。
- 不完整截断长正文：状态提示维持原有 24000 字符预算，状态提示与本轮剧情合计超过 96000 字符时拒绝请求。这是字符上限，不等于模型的上下文 token 上限。
- 不导入 MVU 运行库，不使用 MVU 的数值或补丁协议。目标依赖仍为宿主 SillyTavern 1.18.0 和宿主提供的酒馆助手 4.9.5。
- 不加入 MVU 专用的 JSON/工具调用格式、并发多次请求或自动清理历史。LoreState 已有明确绑定的状态规则条目，本次不额外增加世界书白名单/黑名单扫描；额外剧情规则可通过酒馆预设提供。
- 界面与当前提示词统一称为“状态”。内部 `variableUpdate` 等已有存储键及酒馆助手接口名保留，防止旧配置和接口失效。

真实酒馆下一步需验证：保存两套 API 后刷新仍可切换；正文和状态分别走正确服务；流式与非流式正文均只触发一次更新；重抽、取消、错误密钥、聊天切换、重载后撤销符合上述说明。真实服务的模型遵循率、上下文限制及网络兼容性尚未验证。

## 实现依据

参考 MVU 固定提交 `61010dab47bc3a08a1b626320bf7fc8c9573eca4` 的 [API 方案管理](https://github.com/MagicalAstrogy/MagVarUpdate/blob/61010dab47bc3a08a1b626320bf7fc8c9573eca4/src/function/update/extra_model_api_profiles.ts)、[额外模型调用](https://github.com/MagicalAstrogy/MagVarUpdate/blob/61010dab47bc3a08a1b626320bf7fc8c9573eca4/src/function/update/invoke_extra_model.ts)及消息处理流程，采用“独立请求 → 校验 → 消息写回”的结构，未复制其提示词或移植运行库。

本机酒馆助手源码为 `af21bee2aadef5bf384f618e3456ff15ba9c431d`，清单版本 4.9.5。核对了 `@types/function/generate.d.ts`、`src/function/generate/index.ts`、`responseGenerator.ts` 和 `src/function/variables.ts`：`generateRaw` 的 `custom_api/ordered_prompts/should_silence/generation_id`、`stopGenerationById`、全局状态保存及独立生成触发核心 `GENERATION_AFTER_COMMANDS` 的行为。核心 SillyTavern 提交 `51ad27fb86d39a3daca3adaa970375c9670c12df` 的 `GENERATION_STARTED`、`GENERATION_ENDED` 与 `stopGeneration` 用于时序判断。这是版本化源码证据，尚非本功能的实机运行证据。

本轮另核对 `generate({preset_name})`、`getPresetNames()`、`getPreset()`、`getModelList({apiurl,key})`；`convertGenerateWithCustomPreset` 说明指定预设的采样优先级，`processChatHistoryAndInject` 说明缺少聊天历史占位时会跳过聊天内注入。状态整理内置提示词为本项目适配内容，未引入 MVU 的破限文本。
