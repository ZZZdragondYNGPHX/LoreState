# 隐藏助手兼容与更新 · 当前 0.13.0

隐藏楼层兼容修复最早在 `prototype-v0.9.2` 阶段加入；当前固定稳定版 **`0.13.0`** 与 `main` 均已包含修复。正常新安装使用 [0.13.0 固定组件](../prototype/dist/0.13.0/lorestate-script.json)。

## 为什么隐藏旧楼层会影响状态

隐藏助手会把较早消息排除出模型上下文，但这些消息仍属于真实聊天历史。旧 LoreState 曾在本地回放时跳过隐藏消息：如果首次 full 被隐藏，后续合法 delta 就会从空状态开始重放。

当前行为：

- 初始化起点之后、当前选中回复分支的 AI 楼层都参与本地状态回放，包括隐藏楼层；
- 诊断、快照、EJS 和当前状态使用同一可靠回放事实源；
- 单纯改变隐藏范围不会让历史 checkpoint 失效；
- 真正编辑、删除消息或切换回复分支仍触发历史校验；
- 隐藏助手仍决定哪些正文进入模型上下文，LoreState 不会因此把全部旧剧情重新注入。

## 从旧版本升级

1. 先导出角色卡和聊天备份。
2. 确认只启用一份 LoreState。
3. 将固定安装更新为 `0.13.0`，或重新导入 0.13.0 组件。
4. 刷新酒馆并打开原聊天，检查当前状态与诊断是否连续。
5. 保持原隐藏范围，再发一轮新消息验证。

固定 import：

```js
import 'https://testingcf.jsdelivr.net/gh/ZZZdragondYNGPHX/LoreState@0.12.3/artifact/bundle.js';
```

从 `0.10.6` 或更早版本升级到 0.12.3，状态不会因为隐藏修复而要求重做，但旧 HTML 展示层需要重制为 Template API v2。从 `0.11.0`～`0.12.2` 升级，合法 v2 模板可保留。

## 不要用这些方式“修”历史

不要把合法 delta 全改 full、删除 read 凭据、从消息原文删除 LoreState 块、同时启用多份脚本，或把关闭隐藏助手当作历史修复。

如果原始更新、读取凭据或配置本身已经损坏，应按实际诊断修复；隐藏楼层兼容只保证“隐藏”本身不会把有效历史从本地回放中漏掉。

## 验收

建立一份 full，再生成数轮 delta；隐藏包含初始化的旧楼层后重新打开 LoreState 诊断，状态应仍连续。再测试改变隐藏范围、快照/回档、新生成；最后真正编辑或删除历史状态块，确认真实历史变化仍会被发现。

0.12.0 起的 EJS 只读桥接复用同一可靠回放。真实历史缺口会返回 `history-gap` 等空态原因，而不是冒用最后一个旧好状态。

自动化和模拟宿主回归不等于真实隐藏助手版本、实际模型长聊天和第三方扩展组合已经验收。目标宿主基线仍为 SillyTavern 1.18.0 / Tavern Helper 4.9.5。
