# 隐藏助手兼容与更新

适用于 `prototype-v0.9.2`、当前稳定版 `0.10.6` 和 `main` 的隐藏楼层兼容修复，首次提交为 `32df550`（2026-09-10）。`prototype-v0.9.0` 与 `prototype-v0.9.1` 保持原样。

## 为什么旧楼层后来才报错

隐藏助手会把较早的消息排除出模型上下文。旧 LoreState 回放也跳过隐藏消息：首次 full 初始化一旦被隐藏，后面的合法 delta 就可能从空状态开始应用，报“首次 full，之后 delta”。因此某楼层生成时正常，之后重新诊断却报错，并不一定是该楼层的标签变了。

修复后，初始化起点之后、当前选中回复分支的所有 AI 楼层都参与本地状态回放，包括隐藏楼层。诊断和快照采用相同规则。单纯改变隐藏范围不会使回档前缀失效；真正编辑、删除或切换回复仍会检查历史变化。

隐藏助手继续决定旧正文是否发送给 AI。LoreState 不取消隐藏，也不把旧剧情重新注入；它继续提供当前状态及按需取回的资料。节省正文 token 不等于减少本地历史存储或回放成本。

## 更新现有 0.9.0 脚本

1. 导出当前角色卡和聊天备份。
2. 打开[修复提交的完整脚本代码](https://github.com/ZZZdragondYNGPHX/LoreState/blob/32df550d3c4c1164d9d18b86b686d86864fd43ea/artifact/bundle.js)，通过 Raw 或复制文件内容取得完整 JavaScript；不要复制 GitHub 页面 HTML。后续开发代码见 [main bundle](../artifact/bundle.js)。
3. 在酒馆助手中编辑现有 LoreState 脚本，只替换代码内容。保留原脚本 ID、data、按钮和配置。如果原代码只有远程 import，也将其整体替换为上述完整代码。
4. 保存并刷新酒馆，只保留一个启用的 LoreState。隐藏助手可继续保留最近 5 条或你原有的设置。
5. 打开原聊天，在 LoreState 设置中点击“重新读取当前聊天状态”，再查看诊断。

当前 [0.10.6 固定远程组件](../prototype/dist/0.10.6/lorestate-script.json)和 [main 远程组件](../prototype/dist/main/lorestate-script.json)均包含修复；固定 [0.9.2 远程入口](../prototype/dist/v0.9.2/lorestate-script.json)只代表旧标签代码。使用 `@main` 时刷新脚本可取得开发更新；固定标签不会随分支变化。已有 0.9.0 配置不需要重建；更早版本的升级边界见[模块试卡指南](0.9.0模块条目与试卡.md)。

不要为了消除这一类错误，把合法 delta 强改成 full，或删除 read 凭据。若原始更新、凭据、配置已丢失或被修改，需要针对实际诊断恢复，修复不会补造数据。

## 验收与边界

- 隐藏初始化楼层后，重新读取应保留完整状态，诊断可查看该隐藏楼层。
- 继续一轮，检查最新状态更新；隐藏助手仍只发送设定范围的正文。
- 改变隐藏范围，检查快照和回档仍可用；编辑、删除或切换回复仍应触发相应校验。
- 真正损坏的隐藏更新仍会报错，不能用隐藏绕过校验。过去保存的错误快照保留，不应作为可靠回档点；当前状态重新计算。
