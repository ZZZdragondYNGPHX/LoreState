# 隐藏助手兼容与更新 · 当前 0.12.1

隐藏楼层兼容修复最早在 `prototype-v0.9.2` 阶段加入；当前固定稳定版 **`0.12.1`** 与 `main` 都已包含该修复。`prototype-v0.9.0`、`prototype-v0.9.1` 等旧标签保持原样，不会被回写。

正常新安装直接使用 [0.12.1 固定远程组件](../prototype/dist/0.12.1/lorestate-script.json)。只有明确需要开发版时才使用 [main 远程组件](../prototype/dist/main/lorestate-script.json)。

## 为什么隐藏旧楼层可能让状态报错

隐藏助手会把较早消息排除出模型上下文，但这些消息仍然属于真实聊天历史。

旧 LoreState 回放曾跳过隐藏消息：如果首次 `full` 初始化楼层被隐藏，后面的合法 `delta` 就可能从空状态开始重放，于是出现“首次 full，之后 delta”之类错误。某楼层生成时明明正常，后来重新诊断却出错，根因可能只是回放遗漏了隐藏历史，而不是原始标签突然改变。

修复后：

- 初始化起点之后、当前选中回复分支的 AI 楼层都参与本地状态回放，包括隐藏楼层；
- 诊断、快照和当前状态使用同一套回放规则；
- 单纯改变隐藏范围不会使历史 checkpoint 失效；
- 真正编辑、删除消息或切换回复分支仍会触发历史校验。

隐藏助手仍然决定哪些旧正文发送给 AI。LoreState 不会因为本地回放隐藏楼层，就把所有旧剧情重新塞回模型上下文。

## 当前版本怎么更新

如果你还在使用 0.9.x、0.10.x 或更早固定版本，优先按正常升级方式切到当前 `0.12.1` 固定组件，而不是继续长期粘贴旧修复 commit 的 bundle。

建议：

1. 导出角色卡和聊天备份。
2. 保留原 LoreState 脚本 ID、data、按钮和随卡导出设置。
3. 把原脚本的固定 import 更新为 `0.12.1`，或重新导入 0.12.1 组件后确保只启用一份 LoreState。
4. 刷新酒馆，打开原聊天并重新读取/检查当前状态。
5. 使用隐藏助手保持原来的隐藏范围，观察诊断是否连续。

固定 import：

```js
import 'https://testingcf.jsdelivr.net/gh/ZZZdragondYNGPHX/LoreState@0.12.1/artifact/bundle.js';
```

如果从 `0.10.6` 或更早版本升级到 0.12.1，**状态数据不会因为隐藏修复而需要重做，但旧 HTML 展示层需要按 Template API v2 重制**。从 `0.11.0` / `0.11.1` / `0.12.0` 升级则现有合法 v2 模板可以直接保留。

历史修复提交 `32df550d3c4c1164d9d18b86b686d86864fd43ea` 仅用于复现当时问题，不再是当前推荐安装入口。

## 不要用错误方法“修”隐藏历史

不要为了让报错消失而：

- 把合法 delta 全改成 full；
- 删除读取凭据；
- 从消息原文删掉 LoreState 块；
- 反复新建另一个脚本同时维护同一状态；
- 把隐藏助手关闭后假装历史已经修复。

如果原始更新、读取凭据或配置本身已经损坏，需要按实际诊断修复；隐藏楼层兼容只能保证“隐藏”本身不再把有效历史从本地回放中丢掉。

## 验收方法

在独立测试聊天中：

1. 先建立一份合法完整状态。
2. 再生成几轮 delta。
3. 用隐藏助手把包含初始化的旧楼层隐藏出模型上下文。
4. 在 LoreState 中重新读取/打开诊断。
5. 当前状态应仍连续，隐藏的初始化和增量楼层仍可参与本地回放。
6. 再发一轮新消息，确认模型上下文仍只包含隐藏助手允许的正文范围，而 LoreState 当前状态正确。
7. 改变隐藏范围，检查快照/回档仍可用。
8. 最后真正编辑或删除一个历史状态块，确认 LoreState 仍能发现实际历史变化。

真正损坏的隐藏更新仍然应该报错；隐藏不是绕过校验的手段。

## 与 EJS 动态世界书的关系

0.12.0 起的 EJS 只读桥接也复用 LoreState 的可靠回放结果。隐藏楼层仍属于状态历史，因此桥接不会因为正文被隐藏就自动遗忘这些状态事实。

如果历史存在真实缺口，桥接会返回 `history-gap` 等空态原因，而不是拿最后一个旧好状态冒充当前事实。详见 [EJS / 动态世界书](EJS动态世界书.md)。

## 验证边界

隐藏楼层兼容已有自动化和模拟宿主回归；早期还针对报告问题的合成聊天验证过“隐藏初始化后仍能连续回放”。当前 0.12.1 又包含后续所有状态、模板与 EJS 回归。

但真实 SillyTavern、实际隐藏助手版本、真实模型长聊天性能和不同扩展组合仍需用户环境验收。目标宿主基线仍是 SillyTavern 1.18.0 / Tavern Helper 4.9.5。
