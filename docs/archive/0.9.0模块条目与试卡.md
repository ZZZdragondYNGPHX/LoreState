# 0.9.0 模块条目与试卡

0.9.0 是模块条目设计的重要历史版本。人物、物品、国家和作者自定义类别从这里开始可以拥有各自栏目与更新规则。后续 0.11.x / 0.12.x 保留这一 DataSchema 思路，并继续扩展展示、外观制作和 EJS。

## 历史条目格式

```text
【LoreState模块 v1】
【通用规则】
只记录正文已经确认的持久事实；猜测不写成事实。
【公共栏目】
栏目：地点、时间
明确移动或时间推进时更新。
【模块：人物】
栏目：身体状况、当前目标
受伤或恢复时更新身体状况；明确改变意图时更新当前目标。
【模块：物品】
栏目：持有者、完好状况
交付、拾取或遗失时更新持有者；损坏或修复时更新完好状况。
```

模块条目的核心思路延续至当前，但当前准确解析边界与 0.12.3 结构重建流程以 [状态栏条目创作指南](../状态栏条目创作指南.md) 为准。

## 0.9.0 阶段的加载设计

- 通用规则、公共栏目规则、模块名称与栏目目录始终提供。
- 首次建立状态时提供模块详细规则。
- 已有状态时，当前热档、活动事件、明确提及实体和一跳关联完整档案，会带上其所属模块详细规则。
- 冷档索引本身不等于已读取完整旧档；预算变化会重新计算完整档案和读取权限。
- 未声明“事件”模块时，不要求 AI 自动建立事件实体。

## 更新协议

0.9.0 阶段已经使用 `version="3"` 的 Shared / Entity 外层协议；实体 `type` 必须匹配声明模块。新实体 full 填写自己模块要求的完整栏目，已有实体 delta 只写变化；多个模块更新可放在同一个 LoreState 块中，非法栏目或无效读取会拒绝整轮提交。

概念示例：

```xml
<LoreState version="3" mode="delta">
  <Entity id="P1" mode="delta"><当前目标>返回书店</当前目标></Entity>
  <Entity id="I1" mode="delta"><持有者>守卫</持有者></Entity>
</LoreState>
```

真实生成必须遵守当轮提示的 read 凭据和完整协议。

## 历史试卡重点

| 情境 | 当时应观察到的结果 |
| --- | --- |
| 新聊天首次生成 | 建立实体时填写自己模块的完整栏目 |
| 纯人物对话、其他类别转冷 | 不必携带其他类别完整档案 |
| 人物交付物品 | 跨模块状态一致，未变化字段保留 |
| 正文发现新物品 | 按物品模块建档 |
| 提到冷档唯一名称/编号 | 按读取规则取回；写入仍受 read receipt 校验 |
| 未读取冷档直接改字段 | 整轮拒绝 |
| 国家实体输出人物专用字段 | 报错，不保存半份更新 |
| 修改模块栏目后继续生成 | schema 保护阻止无提示结构变化 |
| 重抽、删尾、刷新、回档 | 按当前回复分支回放 |

当前 Template API v2、显式条目绑定、外观制作、EJS、0.12.3 配置重置均不属于 0.9.0 原始范围。当前完整试卡请看 [FAQ / 试卡清单](../常见问题与试卡清单.md)。
