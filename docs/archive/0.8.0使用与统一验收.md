## 更新与数据边界

先导出测试卡和聊天备份。0.8.0 当时使用旧远程入口；历史新存档和 read 凭据不能供更老的 0.7.x 正确解释，回退需恢复升级前聊天备份。

快照、聊天作者配置及读取凭据位于聊天变量；脚本保存未来新聊天默认配置。角色卡导出不能替代聊天备份。

## 作者初始档案和文字约束

当时入口：魔法棒 → LoreState → 设置 → 初始档案与字段约束。示例公共栏目 `地点、时间`，实体栏目 `状态`：

```html
<section><h3>地点</h3><p data-lore-field="地点"></p><h3>时间</h3><p data-lore-field="时间"></p></section>
<article data-lore-entity><h3 data-lore-name></h3><p data-lore-field="状态"></p></article>
```

初始档案：

```xml
<LoreState version="3" mode="full">
  <Shared><地点>港口</地点><时间>第三天清晨</时间></Shared>
  <Entity id="P1" name="访客" identity="约定来访者" mode="full" presence="cold">
    <状态>等待</状态>
  </Entity>
</LoreState>
```

字段规则：

```json
{
  "shared": {
    "地点": {"required": true},
    "时间": {"noRemove": true}
  },
  "entity": {
    "状态": {"enum": ["等待", "完成", "未知"]}
  }
}
```

`required` 表示必填；`noRemove` 禁止移除已有内容；`enum` 要求完整栏目文字等于某个允许值。程序不会把非法输出猜改成合法值，任一错误导致整轮不提交。

留空初始档案时当时保持首轮 full；填写后初值先于首轮生效，首轮用 delta。初值事实来源楼层未知，不伪装成模型确认。

## 冷档当轮更新

输入明确提及稳定 ID/唯一名称或通过有限一跳关联时，可完整取回冷档。只有最终提示中完整保留的冷档才列入当轮可更新清单；模型需原样复制提示中的 `read` 凭据，本地会核对前态、配置和加载编号。

读取冷档不自动转热。旧无 read 标签仍可回放，但不能直接修改冷档。历史状态或配置改变后后续凭据可能失效。

## 存储与续写

当时诊断页显示快照数量、共享正文数量和存档 MiB；历史版本保留，相同正文去重。0.8.0 对“继续生成”同一回复明确中止，不实现同层续写合并。

## 历史实机测试清单

| 场景 | 当时预期 |
| --- | --- |
| 旧聊天升级 | 原状态、旧快照与分支保留 |
| 初值预览 | 港口、时间、访客等待可见；尚未写入 |
| 初值应用 | 空聊天应用后首轮用 delta 接续初值 |
| 约束拒绝 | 非法值导致整轮失败，不部分提交 |
| 冷档召回 | 完整加载目标冷档，有效 read 允许同轮更新 |
| 未读保护 | 未完整召回时直接改冷档应拒绝 |
| 历史编辑 | 受影响的后续凭据失效 |
| 重抽/删尾 | 按更新前状态重抽，删尾回退 |
| 回档 | 恢复旧快照后新回复接续 |
| 配置隔离 | 新旧聊天使用各自冻结配置 |
| 同层续写 | 当时中止，不追加第二状态块 |
| 持久化 | 刷新/重开后历史配置与状态可回放 |

本文继续保留是因为回归测试会使用其中的初始档案/字段规则作为历史输入样本；当前用户流程请勿从本页复制。
