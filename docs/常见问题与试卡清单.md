# 常见问题与试卡清单 · 当前 0.13.0

当前安装与作者流程见 [文档目录](README.md) 和 [作者入门](作者入门.md)。

## 首次外观制作为什么读错条目

0.12.1 起已改为显式绑定。当前 0.13.0 的正确流程是：**选择世界书与状态栏条目 → 确认绑定状态栏条目 → 打开外观制作**。

如果已确认条目后来被删除，当前实现应留空并要求重新选择，而不是静默改用第一条。仍出现旧行为时先核对实际加载 ref，确认不是旧固定标签。

## 条目有字段，HTML 没显示

DataSchema 来自 `【LoreState模块 v1】`；HTML 只决定展示。公共字段用 `data-lore-shared`，实体模块用 `data-lore-each`，each 内用 `data-lore-field`。HTML 故意省略字段不会删除状态；引用未声明字段会在校验阶段报错。

## 旧 HTML 升级后不显示

0.11.0 起使用 Template API v2，文档根需要 `data-lore-template="2"`。0.10.6 及更早模板不会自动转换，需要重新制作 v2 外观。

从 0.11.0～0.12.2 升级到 0.12.3，合法 v2 模板无需重制。

## 想增删/改名栏目怎么办

不要只改 HTML，也不要让新 schema 直接套旧聊天状态。

0.12.3 在 **规则配置 → 聊天维护** 提供 **彻底删除旧配置**。输入 `删除旧配置` 后执行，会清除本脚本配置和当前聊天的 LoreState 状态、快照、回档、更新绑定及恢复备份；保留聊天正文、世界书和全局 API 预设。其他旧聊天不会被批量删除，但会因配置代次变化停用，重新启用时清理旧状态。

这是不可撤销的结构重建流程，重要聊天先备份。随后重新绑定模块条目、制作/应用匹配新 DataSchema 的 HTML，再保存启用。

## 正文末尾还显示 XML

检查 HTML/聊天是否已启用、本卡局部显示过滤是否存在、原始消息中的 LoreState 块是否完整合法。显示隐藏与状态解析是两件事，不要为了隐藏 XML 手工删除原始状态块。

## 没有第一份状态

第一次参与回放的有效 AI 回复需要建立完整状态，后续才使用 delta；新实体第一次建档也要提供该模块要求的完整字段。

检查世界书/条目是否选对、是否确认绑定、HTML 是否保存并启用、下一轮状态提示是否包含正确 DataSchema。新测试卡优先从新聊天第一轮开始验证。

## 改一件事，其他事实消失

增量是“只提交变化的栏目”，但一个栏目内部仍是完整替换。新值必须保留该栏目里仍然成立的旧事实。

## 冷档看得见却不能更新

本地查看/EJS 读取不等于获得写权限。冷档写入仍受当轮 LoreState 读取凭据和状态校验。不要伪造 read receipt 或删除校验信息。

## 转冷后仍占提示空间

可能是当前输入准确提到它、热档/活动事件通过 `links` 关联它、它仍属于活动事件所需资料，或冷档索引保留了简短召回信息。关联是一跳、有向读取，不无限递归。

## 事件为什么不能自动完成

LoreState 没有后台计时器。截止时间到达只表示应该处理，不代表剧情已经完成。只有正文明确完成/取消后，事件状态才应更新并按规则转冷。

## 提示超预算怎么办

减少重复世界书规则、把无关实体转冷、清理无用 links、模板冷档区域使用 limit、避免把大段历史放进公共常驻栏目。不要为了过预算静默删除已确认事实。

## EJS 动态世界书没生效

确认：当前稳定版 0.13.0；ST-Prompt-Template 已安装并处理生成内容；EJS 在本轮实际参与生成的世界书条目中；`LoreState.ready === true`；路径使用稳定实体 ID（如 `entities.P1.fields.好感度`）。历史缺口等情况下桥接会返回空态。

详见 [EJS 指南](EJS动态世界书.md)。

## 额外模型/API 更新失败

0.12.3 支持酒馆助手 OpenAI 兼容路径、Chat Completions、Responses、Anthropic Messages。检查协议、地址/完整端点、密钥、自定义请求头、模型、请求预设、总超时和浏览器跨域限制。

失败诊断保留在本地；取消、聊天切换、配置变化或分支变化会阻止迟到结果写入。详见 [额外模型与 API 预设](额外模型与API预设.md)。

## 一次完整试卡

在独立测试聊天至少检查：

1. 固定加载 **0.13.0**，只启用一份 LoreState。
2. 选择非第一条世界书模块条目并确认绑定；刷新/切页后选择仍正确。
3. 生成/应用一次合法 v2 HTML，预览后保存并启用聊天。
4. 首次回复建立完整公共状态和至少一个实体。
5. 下一轮只改一项，其他栏目继续继承。
6. 至少测试一次跨模块变化。
7. 实体转冷后本地完整档案仍在；按准确 ID/名称召回并验证写入权限。
8. 创建未完成事件，确认人物离场不等于事件完成。
9. 故意写错字段，确认整轮原子拒绝而不是半提交。
10. 测编辑、重抽、删尾、快照回档、隐藏旧楼层。
11. 刷新页面并切换聊天，确认不串档。
12. 如使用额外模型，测试重试、取消、手动重算、撤销，以及实际目标 API 协议。
13. 如使用 EJS，测试 ready、区间边界、缺字段、swipe/重生成/回档。
14. 如准备换 schema，在测试副本验证 0.12.3 的“彻底删除旧配置 → 重新绑定/启用”流程。
15. 导出角色卡并重新导入，核对脚本数据、世界书绑定、v2 外观与过滤规则。

角色卡导出不是聊天备份；聊天状态、冷热档、回档与历史快照属于聊天。自动化覆盖不替代真实 SillyTavern、实际模型、手机和长期游玩验收。
