# 常见问题与试卡清单 · 当前 0.12.1

当前版本入口见[作者文档目录](README.md)。使用隐藏助手后旧楼层突然报 full/delta，请先看[隐藏助手兼容与更新](隐藏助手兼容与更新.md)。

## 为什么首次外观制作读错了条目

`0.12.1` 已修复首次设置时刷新世界书/切换页签后选择丢失并误用第一条的问题。

当前流程必须是：**选择世界书与状态栏条目 → 确认绑定状态栏条目 → 打开外观制作**。如果仍出现错误，先确认实际加载的是 0.12.1 或更新后的 main，而不是旧固定标签。

如果已经确认绑定的条目后来被删除，当前实现会留空并要求重新选择，不应静默改用第一条。

## 为什么条目写了字段，HTML 里没有

当前 DataSchema 来自 `【LoreState模块 v1】` 条目；HTML 只决定展示。

- 公共字段用 `data-lore-shared`；
- 实体模块用 `data-lore-each="模块名"`；
- 模块字段在 each 内用 `data-lore-field`；
- HTML 可以故意省略字段，这不会删除状态数据。

如果模板引用了条目没有声明的字段，会在校验阶段报错。完整语法见 [Template API v2 指南](HTML模板适配指南.md)。

## 为什么旧 HTML 升级后不显示

`0.11.0` 起展示层使用 Template API v2，文档根需要 `data-lore-template="2"`。`0.10.6` 及更早模板不会自动转换；旧原文会保留，但需要重新制作 v2 外观。

从 `0.11.0` / `0.11.1` / `0.12.0` 升级到 `0.12.1`，合法 v2 模板无需重制。

## 为什么正文末尾还显示 XML

检查：

1. 是否已经保存 HTML 并启用当前聊天；
2. 本卡局部过滤规则是否启用；
3. LoreState 维护的显示过滤/提示词过滤是否存在；
4. 原始消息中的状态块是否完整合法。

显示隐藏和状态解析是两件事。不要为了隐藏 XML 而从原始消息里手工删除状态块，原文是历史回放依据。

## 为什么没有第一份状态

第一次参与回放的有效 AI 回复需要建立完整状态；后续才使用 delta。新实体第一次建档也要提供该模块要求的完整字段。

先检查：

- 世界书与状态栏条目是否选对；
- 是否点击了 **确认绑定状态栏条目**；
- HTML 是否已保存并启用聊天；
- 下一轮状态提示是否包含正确 DataSchema；
- 是否在一个已有大量历史但从未初始化 LoreState 的聊天中途首次启用。

开场白不是可靠的唯一初始化来源。建议新测试聊天从第一轮玩家发言开始验证。

## 为什么改一件事，其他事实消失了

增量是“只提交变化的栏目”，但**一个栏目内部的文字仍是完整替换**。

原值“保管钥匙，左臂受伤”，后来归还钥匙，如果伤势仍在，新值必须继续包含“左臂受伤”。只写“已归还钥匙”会把同栏目里的伤势覆盖掉。

## 为什么冷档看得见，却不能随便更新

查看本地档案或 EJS 读取并不自动发放写入权限。冷档更新仍受 LoreState 的按需读取与 read receipt 校验。

需要更新冷档时，应让它通过当前正常读取/唤醒流程进入可靠生成上下文；不要伪造凭据或删除校验信息。

## 为什么转冷后仍占提示空间

可能原因：

- 当前输入准确提到了它；
- 热档/活动事件通过 `links` 关联到它；
- 它仍属于活动事件需要的资料；
- 冷档索引仍保留简短召回信息。

关联是一跳、有向读取，不会无限递归。清理已经无用的 links 比删除历史事实更合适。

## 为什么事件不能转冷

未完成事件需要继续保持可用。时间到达只表示“应该处理”，不会自动判定事件已完成。

只有正文明确完成/取消，并且状态把事件标为已结束后，才适合按规则转冷。LoreState 没有后台计时器或自动剧情模拟。

## 提示超预算怎么办

LoreState 的状态/规则预算按字符计，不等于模型 token。常见处理：

- 删除世界书规则中重复解释；
- 把暂时无关实体转冷；
- 移除不再需要的 links；
- 冷档展示使用 Template API 的 limit；
- 不要把大段历史塞进公共常驻栏目。

不要为了过预算而静默删除已确认的状态事实。

## EJS 动态世界书为什么没有生效

检查：

1. 当前 LoreState 至少是 0.12.0；推荐当前 0.12.1。
2. ST-Prompt-Template 已安装并启用“处理生成内容”。
3. EJS 写在本轮实际参与生成的世界书条目，而不是 HTML 模板。
4. `LoreState.ready === true`。
5. 路径使用真实稳定 ID，例如 `entities.P1.fields.好感度`，不是按姓名猜路径。

历史缺口、聊天切换、无法确认生成前态等情况下桥接会返回空态，而不是冒用旧状态。见 [EJS 指南](EJS动态世界书.md)。

## 额外模型更新失败怎么办

检查 API 地址、密钥、模型、当前/指定预设和总超时。失败输出保留在本地诊断中；取消、聊天切换、配置变化或分支变化会阻止迟到结果写入。

最新回复状态失败时可使用手动重算；尾部状态块截断时先预览正文/截断分界，再确认重算。详见 [额外模型与 API 预设](额外模型与API预设.md)。

## 什么会随角色卡导出

脚本配置、HTML 和命名预设依赖脚本数据随卡导出设置。聊天状态、冷热档、回档与历史快照属于聊天本身。

角色卡导出不是聊天备份。重要游玩进度应另外备份聊天，并在重新导入后实际检查。

## 一次完整试卡

在独立测试聊天里至少检查：

1. 固定加载 `0.12.1`，只启用一份 LoreState。
2. 选择非第一条世界书状态栏条目，确认绑定；刷新/切页后仍保持选择。
3. 用外观制作台生成一次草稿，或应用现成 v2 模板；预览后保存并启用聊天。
4. 首次 AI 回复建立完整公共状态和至少一个实体，显示正确。
5. 下一轮只改变地点，未变化字段继续保留。
6. 物品/人物/国家至少测试一个跨模块同步变化。
7. 把一个实体转冷，确认本地完整档案仍在，模板冷档区域按预期显示。
8. 通过准确 ID/名称触发读取，再验证合法更新流程。
9. 创建未完成事件，参与人物离场后事件仍可继续影响状态；完成后才转冷。
10. 故意写错一个字段，确认整轮不部分提交；修复原文后重新回放。
11. 测编辑、重抽、删尾、快照回档和隐藏旧楼层。
12. 刷新页面并切换聊天，确认配置/状态不串档。
13. 如使用额外模型，测试取消、失败重试、手动重算与撤销。
14. 如使用 EJS，测试 ready、边界值、缺字段、swipe/重生成/回档。
15. 导出角色卡，在测试副本重新导入，核对脚本数据、世界书绑定、v2 外观与过滤规则。

当前自动化覆盖构建、Node 与模拟宿主，但真实 SillyTavern、真实模型、手机和长期游玩仍应由作者验收。排错时提供版本、操作步骤、错误楼层和去除隐私后的诊断即可，不需要公开整份私人聊天。
