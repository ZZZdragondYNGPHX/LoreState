# 状态栏条目创作指南 · 当前模块格式

当前作者条目使用 **`【LoreState模块 v1】`** 格式。人物、物品、国家、事件等模块可以拥有各自不同的栏目；旧 0.7.x“所有实体共用同一套栏目”的写法只属于历史版本，不再是当前规则。

一条好的状态维护规则要回答：**记什么、什么时候更新、没有证据时怎么办、哪些对象需要持续加载。** 不需要重复角色卡，也不要再要求模型每轮重抄整张状态表。

## 最小结构

```text
【LoreState模块 v1】
【通用规则】
只记录正文已经确认的持久事实；猜测、传闻和计划不视为既成事实。
新档案只填写已知内容，未知写“未知”。跨模块变化在同一轮保持一致。

【公共栏目】
栏目：地点、时间
明确移动或剧情时间推进时才更新。

【模块：人物】
栏目：身体状况、当前目标
受伤或恢复时更新身体状况；明确改变意图时更新当前目标。

【模块：物品】
栏目：持有者、完好状况
交付、拾取或遗失时更新持有者；损坏或修复时更新完好状况。
```

第一行是格式标记。每个公共/模块分区的首个非空行使用 `栏目：`；多个栏目用中文顿号 `、` 分隔。模块至少一个、最多 16 个且不能重名。

名称应使用文字或下划线开头，后续可包含文字、数字、下划线和连字符，最长 40 字符。公共栏目最多 32 个；所有实体模块合计最多 32 个不同栏目名。条目总长度和本轮组装后的规则/档案都受 24000 字符预算约束。

## 公共栏目放什么

公共栏目适合整个场景共用、每轮都可能需要的事实，例如：

- 地点、时间、天气阶段；
- 玩家当前身份或全局任务阶段；
- 不属于某一个实体、但持续影响当前场景的事实。

公共栏目不是“每轮必须改”。地点没有移动就继承旧值；时间没有推进就不要为了换一种说法而重写。

不要把所有人物关系、所有国家历史塞进一个巨大的公共栏目，否则实体转冷也无法减少这部分提示内容。

## 不同模块可以有不同栏目

模块就是当前 schema 的分类。常见设计：

| 模块 | 适合的栏目示例 |
| --- | --- |
| 人物 | 身体状况、当前目标、关系描述、身份状态 |
| 物品 | 持有者、完好状况、用途、当前位置 |
| 国家 | 政局、外交、战争状态 |
| 事件 | 事项、进展、触发条件、截止时间 |
| 组织 | 领导者、立场、当前行动 |
| 地点 | 控制者、危险、当前状态 |

不同模块可以使用完全不同的字段。真正的 DataSchema 来自条目；Template API v2 HTML 只选择“显示哪些字段、显示在哪里”。

## 给每个栏目写更新条件

不要只写“记录当前状态”，最好明确：

```text
【模块：人物】
栏目：身体状况、当前目标
身体状况：只记录正文明确发生的伤势、疲劳、恢复和持续异常；没有证据时不自行痊愈。
当前目标：只有人物明确改变当前意图或剧情已使旧目标失效时更新；普通交谈不自动改变目标。
```

一个栏目内部仍是**完整当前值替换**。例如原值“保管钥匙，左臂受伤”，后来归还钥匙但伤势仍在，新值应该保留“左臂受伤”，不能只写“钥匙已归还”。

推荐每个栏目保持短而完整。状态是当前事实，不是变化日志；不必保存“从 A 变成 B”的过程，除非这个过程本身仍是当前有用事实。

## 写清未知与证据边界

推荐在通用规则中明确：

```text
只记录正文已经确认的结果。
猜测、计划、传闻与未发生事件不视为既成事实。
新档案缺少的信息写“未知”，不凭空补重大事实。
人物自述如果尚未得到确认，可在文字中标明“自称/未证实”。
```

这样可以减少模型为了填满栏目而发明伤势、身份、关系或事件结果。

## 跨模块变化要同轮一致

模块化之后，更需要提醒模型不要只改一边。例如人物把钥匙交给守卫：

- 人物相关栏目如果记录持有物，应同步去掉钥匙；
- 物品“持有者”应同时改为守卫；
- 如果这次交付完成了一个事件，事件“进展”也应同步更新。

把“跨模块变化同轮保持一致”放在通用规则里通常比在每个模块重复更稳。

## 热档、冷档与召回

不再需要每轮把所有实体完整发送给模型。与当前行动有关的对象保持热档；暂时无关的对象可以转冷，完整档案仍保存在本地。

冷档被用户准确提及、被活动对象通过关联带出，或满足其他读取条件时可以在本轮重新提供。**读取冷档不等于自动改变冷热状态。** 冷档写入仍受 LoreState 的读取凭据与状态校验约束。

不要为了节省 token 删除已确认事实；让无关实体转冷即可。冷档索引只是召回线索，不是第二份完整档案。

## 关联只写当前有用的对象

实体可以通过 `links` 指向当前需要一起读取的对象。关联是有向的一跳读取，不自动反向，也不无限递归；不要把整个关系网都挂上去，否则大量冷档会重新进入提示。

例如“送货事件”关联负责的商人和货物通常足够，不需要把商人所属国家的全部组织都连进来。

## 未完成影响适合做事件

会在未来继续影响剧情、但责任人物可能已经离场的事情，适合单独建为事件，例如：欠款、追杀、交付承诺、战争影响、倒计时。

推荐事件规则：

```text
【模块：事件】
栏目：事项、进展
事项：记录触发条件、截止时间或完成条件。
进展：只记录正文已经确认的结果。
有明确责任方且尚未完成的持续影响，应建立事件档案。
时间到达只表示需要处理，不代表事件自动完成。
只有正文确认完成或取消后，事件才可结束并按需转冷。
```

LoreState 不在后台运行计时器，也不会自行推演事件结果；实际剧情仍由模型产生。

## 栏目约束与数值

状态值以文字保存。可以把“好感度”写成 `-63` 这样的数字文本，但 LoreState 本身不负责自动加减、战斗结算或游戏公式。

如果需要“数值区间决定本轮世界书规则”，可以使用 0.12.0 起提供、当前 0.12.1 继续兼容的 [EJS / 动态世界书只读桥接](EJS动态世界书.md)。它只读取当前状态，不建立第二套变量，也不写回 LoreState。

## HTML 不再定义栏目

Template API v2 中：

- 公共值使用 `data-lore-shared`；
- 实体区域使用 `data-lore-each="模块名"`；
- 区域内用 `data-lore-field` 读取该模块字段；
- 可以只展示部分字段、重复字段、同类多区域或冷档区域。

因此“隐藏某字段”只是换皮肤，不会从状态里删除这个字段。完整接口见 [HTML 模板适配指南](HTML模板适配指南.md)。

## 修改现有条目

只修改自然语言更新规则、但栏目集合不变时，可以继续使用现有 schema。

增删、改名公共栏目或模块栏目属于结构变化。现有配置有 schema 保护，不应靠改 HTML 绕过；建议在独立测试配置和新聊天中验证新的结构，再决定如何迁移使用。

当前 0.12.1 首次配置时，选择世界书和条目后先点击 **确认绑定状态栏条目**，再进入外观制作。完整流程见 [作者入门](作者入门.md)；可直接复制的当前示例见 [module-example.txt](../prototype/module-example.txt)。
