# LoreState 版本管理

本项目同时保留当前 Tavern Helper 脚本与历史原生扩展。当前 Tavern Helper **固定稳定版是 `0.12.3`**；`main` 是唯一长期开发分支。

## 唯一活动开发线

- `main` 是唯一长期开发分支，也是唯一活动远程开发入口。
- `prototype/` 是维护源。
- `artifact/bundle.js` 是 main 的生成运行代码，不手工维护。
- 普通修复与功能开发从 main 创建短期分支，完成后合回 main 并删除。
- 不保留 `release-*`、裸版本号 branch、长期 hotfix/debug 分支。

## 正式版本

正式版本只用**不可移动 Git tag**表示，例如 `0.12.1`。

禁止：

- 创建 `0.12.3`、`1.0.0` 这种语义版本名 branch；
- 移动、覆盖、重建已发布 tag；
- 让固定版本 loader 引用 `@main`；
- 在旧固定 tag 上追加修复后仍沿用旧版本号；
- 用额外 loader + 旧 bundle 长期冒充新版本。

需要修正式版时，在当前维护线修复并验证，然后发布新的 patch tag。

## 构建

开发版：

```sh
npm run build
```

生成：

- `artifact/bundle.js`
- `prototype/dist/main/lorestate-script.json`
- `prototype/dist/main/receipt.json`

main loader 只能引用 `@main/artifact/bundle.js`。

当前 `0.12.3` 已发布。下一 patch 示例：

```sh
npm run build -- 0.12.4
```

这会额外生成 `prototype/dist/0.12.4/`。固定 loader 必须只引用 `@0.12.4/artifact/bundle.js`；提交维护源和生成物并完成检查后，tag 再指向完全相同的提交。

构建产物不得手工维护；修改 `prototype/`、构建脚本或远程分发逻辑后都必须重新构建。

## 短期分支命名

允许：

- `fix/<slug>`：缺陷修复；
- `feat/<slug>`：功能开发；
- `chore/<slug>`：仓库/构建/文档维护；
- `debug/<version>-<slug>`：针对固定版本的临时复现。

短期分支完成后删除。版本号只属于 tag，不属于 branch。

## 固定版本问题

排查固定版本问题时：

1. 确认用户实际 import 的 ref；
2. 从该 tag 的精确 commit 复现；
3. 必要时创建短期 debug 分支；
4. 日志/诊断钩子只留在临时分支；
5. 根因修复进入维护源并补回归；
6. 重新 build/check/test；
7. 合回 main，删除 debug 分支；
8. 对外稳定交付时发布新 patch tag。

不要从今天的 main 行为反推旧 tag。

## 历史固定版本边界

- `0.10.0`、`0.10.1`、`0.10.2`：历史正式 tag。
- `0.10.3`：原误建版本号 branch 的 SHA 已固化为同名兼容 tag；不再开发。
- `0.10.0`～`0.10.3` 早于当前固定版本目录规范，没有新的 `prototype/dist/<version>/` 组件目录；不补写历史。
- `0.10.4`：首个完整遵守“固定入口 + receipt + bundle + tag 同提交”的版本。
- `0.10.5`：加入失败/截断状态块的重算与预览修复。
- `0.10.6`：修复柏宝书长摘要 + Grid 主题导致的楼层横向溢出；旧模板接口仍属于 v1 时代。
- `0.11.0`：引入 Template API v2；展示层破坏性升级，v3 状态/schema/快照不变。
- `0.11.1`：加入 API 辅助外观制作、条件显隐与 class 映射；已有 v2 模板继续兼容。
- `0.12.0`：加入可选 ST-Prompt-Template / EJS 只读桥接；v3 状态和 v2 外观不变。
- **`0.12.1`：前一固定版。修复首次条目选择在刷新/切页后丢失，新增“确认绑定状态栏条目”，并让首次 HTML 制作读取正确条目。**
- `0.12.2`：浅色控制中心，五区导航，合并更新/重算入口；保留 v3 状态、v2 HTML 和快照。
- **`0.12.3`：配置重置、多协议 API、酒馆预设桥接和思考程度。**
- `prototype-v0.x`：更早的原型历史，只读保留。
- 根目录 `package.json` / `manifest.json` 的 `0.2.1`：历史原生扩展版本，不代表当前 Tavern Helper 脚本。

各版本证据见 [发布材料](发布材料/README.md)。旧发布说明保留当时事实，不会为了当前版本去重写旧 tag 的行为。

## 升级语义

当前推荐固定安装 `0.12.3`。

- `0.11.0` / `0.11.1` / `0.12.0 → 0.12.3`：现有 v3 状态、快照和合法 Template API v2 HTML 不需要迁移。
- `0.10.6` 或更早 → 0.12.3：状态数据升级按对应历史边界处理；旧 HTML 原文保留，但当前展示需要重制为 Template API v2。
- 固定版只在明确升级 import / 重新导入组件时变化，不随 main 自动前进。

## 发布前检查

新固定版本至少完成：

1. `npm run build -- <version>`；
2. `npm run check`；
3. `npm test`；
4. 涉及 UI、模板或宿主事件时运行 `node scripts/test-browser.mjs`；
5. 涉及 EJS 时按需要运行 `node scripts/test-ejs.mjs`；
6. 检查 `git diff` / `git status`；
7. 确认 `prototype/dist/<version>/lorestate-script.json` 只引用 `@<version>`；
8. 确认 receipt 与实际 bundle 对齐；
9. tag 指向通过检查的同一提交；
10. 未完成真实 SillyTavern/实际模型验收时，文档必须明确标注，不能把自动化等同于人工通过。
