# LoreState 版本管理

本项目同时保留当前 Tavern Helper 脚本与历史原生扩展。为了避免版本号、分支、构建产物互相污染，当前 Tavern Helper 维护线统一遵守本文件。

## 唯一活动开发线

- `main` 是唯一长期开发分支，也是唯一活动远程开发入口。
- `artifact/bundle.js` 是 `main` 的运行代码；`prototype/` 是其维护源。
- 普通修复与功能开发从当前 `main` 创建短期分支，完成后回到 `main`。
- 长期不得保留 `release-*`、版本号分支、一次性 `source-port*`、`hotfix/*-debug` 等分支。

## 正式版本

正式版本只用不可移动的 Git tag 表示，例如 `0.10.2`、`0.10.4`。

禁止：

- 创建名为 `0.10.4`、`1.0.0` 等语义版本号的 branch；
- 移动、覆盖或重建已经发布的 tag；
- 让固定版本入口引用 `@main`；
- 在固定版本上直接追加修复后仍沿用同一个版本号。

需要修正式版时，从对应 tag 或当前 `main` 做修复，验证后发布新的 patch 版本。

## 构建

开发版：

```sh
npm run build
```

生成：

- `artifact/bundle.js`
- `prototype/dist/main/lorestate-script.json`
- `prototype/dist/main/receipt.json`

固定版本在打 tag 前执行：

```sh
npm run build -- 0.10.4
```

这会额外生成 `prototype/dist/0.10.4/`，其 loader 必须固定引用 `@0.10.4/artifact/bundle.js`。提交这些生成物并完成检查后，tag 必须指向这个完全一致的提交。

构建产物禁止手工维护；任何 `prototype/`、`scripts/` 或远程分发修改都必须重新构建。

## 分支命名

允许的短期分支前缀：

- `fix/<slug>`：缺陷修复；
- `feat/<slug>`：功能开发；
- `chore/<slug>`：仓库、构建、文档维护；
- `debug/<version>-<slug>`：针对固定版本的临时诊断，只用于复现，不得成为正式安装入口。

短期分支完成后必须删除。不得用 `release-*` 或裸版本号充当开发分支。

## 诊断与 hotfix

临时诊断代码不得写入 `main` 的远程入口，也不得长期存在于 `artifact/`。

排查固定版本问题时：

1. 先确认用户实际加载的 ref；
2. 从该 tag 的精确 commit 创建 `debug/...` 分支；
3. 诊断钩子只能留在该临时分支；
4. 找到根因后修改维护源并加入测试；
5. 重新构建；
6. 合回 `main`；
7. 删除 debug 分支；
8. 需要对外稳定交付时发布新的 patch tag。

不得用“额外 loader + 旧 bundle”长期冒充新版本。

## 当前历史边界

- `0.10.0`、`0.10.1`、`0.10.2` 已有正式 tag，视为历史不可变版本。它们早于当前固定版本目录规范，只保留 tag 下的源码与 `artifact/bundle.js`，没有 `prototype/dist/<version>/` 导入组件；不得移动旧 tag 或补写其历史。
- 仓库曾错误创建名为 `0.10.3` 的 branch；它只视为历史 RC/兼容引用，冻结后不得继续提交，也不得作为今后版本管理范例。
- 为避免 branch/tag 同名带来的 CDN 与人工判断歧义，清洗后的下一次正式发布从 `0.10.4` 开始；它也将是第一个完整遵守“固定入口 + 收据 + bundle + tag 同提交”规则的版本。
- `prototype-v0.x` 系列属于更早历史，只读保留。
- 根目录 `package.json` / `manifest.json` 中的 `0.2.1` 属于旧原生扩展，不代表当前 Tavern Helper 脚本版本。

## 发布前检查

发布固定版本前至少完成：

1. `npm run build -- <version>`；
2. `npm run check`；
3. `npm test`；
4. 涉及 UI、模板或宿主事件时运行 `node scripts/test-browser.mjs`；
5. 确认 `git diff` 与 `git status` 干净；
6. 确认 `prototype/dist/<version>/lorestate-script.json` 只引用 `@<version>/artifact/bundle.js`；
7. 确认 tag 指向通过上述检查的同一提交；
8. 真实 SillyTavern/真实模型尚未验收时，文档必须明确写“未完成真实宿主验收”，不得把自动化测试等同于人工验收。
