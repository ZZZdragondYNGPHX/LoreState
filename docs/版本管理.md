# LoreState 版本管理 · 当前 0.13.1

当前 Tavern Helper 固定稳定版是 **`0.13.1`**；`main` 是唯一长期开发分支。仓库根目录 `package.json` / `manifest.json` 的 `0.2.1` 属于旧原生扩展，不是当前脚本版本。

## 唯一活动开发线

- `main`：唯一长期开发分支和开发远程入口。
- `prototype/`：维护源。
- `artifact/bundle.js`：main 生成运行代码，不手工维护。
- 普通工作使用短期 `fix/*`、`feat/*`、`chore/*`；固定版本诊断可用 `debug/<version>-<slug>`。
- 完成后删除短期分支；不保留 `release-*`、裸语义版本 branch 或长期 hotfix/debug 分支。

## 正式版本

正式版本只用**不可移动 Git tag**表示，例如当前 `0.13.0`。

禁止：创建 `0.12.3`/`1.0.0` 这种版本号 branch；移动/覆盖已发布 tag；让固定 loader 引用 `@main`；在旧 tag 上追加修复后仍沿用旧版本号；用额外 loader + 旧 bundle 冒充新版本。

固定版需要修复时，从当前维护线修复并验证，然后发布新的 patch tag。

## 构建

开发版：

```sh
npm run build
```

生成 `artifact/bundle.js`、`prototype/dist/main/lorestate-script.json`、`prototype/dist/main/receipt.json`，main loader 只能引用 `@main/artifact/bundle.js`。

当前 `0.13.1` 已发布。下一 patch 示例：

```sh
npm run build -- 0.13.2
```

固定 loader 只能引用 `@0.13.1/artifact/bundle.js`；提交维护源和生成物、完成检查后，再让 tag 指向同一提交。

## 固定版本问题

1. 确认用户实际 import/ref。
2. 从该 tag 的精确 commit 复现。
3. 必要时建立短期 `debug/<version>-<slug>`。
4. 诊断钩子只留临时分支。
5. 根因修复进入维护源并补测试。
6. build/check/test。
7. 合回 main 并删除临时分支。
8. 需要稳定交付时发布新 patch tag。

不要用今天的 main 行为反推旧 tag。

## 版本边界

- `0.10.0`～`0.10.2`：历史正式 tag。
- `0.10.3`：原误建版本号 branch 的 SHA 固化为同名兼容 tag；不再开发。
- `0.10.4`：首个完整采用“固定入口 + receipt + bundle + tag 同提交”的版本。
- `0.10.5`：失败/截断状态块重算与预览修复。
- `0.10.6`：楼层布局兼容，仍属于 Template API v1 时代。
- `0.11.0`：Template API v2。
- `0.11.1`：外观制作、条件显隐、class 映射。
- `0.12.0`：ST-Prompt-Template / EJS 只读桥接。
- `0.12.1`：首次条目显式绑定与首次 HTML 制作修复。
- `0.12.2`：浅色控制中心、五区导航、统一更新/恢复入口。
- `0.12.3`：配置重置、多协议 API、酒馆预设桥接、思考程度与默认值调整。
- `0.13.0`：更新前核对、自定义核对规则、随卡规则副本、更新默认值与导出准备。
- **`0.13.1`：当前固定版；核对判断规则来源收敛到状态栏条目/自定义规则，并动态提供精确 schema path。**
- `prototype-v0.x`：更早原型历史，只读保留。

各版本发布时的事实与验证边界见 [发布材料](发布材料/README.md)。

## 升级语义

当前推荐固定安装 `0.13.1`。

- `0.12.3 → 0.13.0`：保留 v3 状态、作者档案、快照与 v2 外观；升级后保存状态绑定并执行导出准备，可补齐新随卡配置。无需重建聊天。
- `0.11.0`～`0.12.2 → 0.12.3`：合法 Template API v2 HTML、v3 状态和快照无需因版本升级迁移。
- `0.10.6` 或更早 → `0.12.3`：旧 HTML 原文可保留，但展示层需重制为 Template API v2；状态数据按对应历史边界处理。
- 固定版只在用户明确升级 import/重新导入组件时变化，不随 main 自动前进。
- **主动“彻底删除旧配置”不是普通版本升级。** 它用于重建 DataSchema，会清理当前配置和当前聊天 LoreState 数据，详见 0.12.3 发布说明。

## 发布前最低检查

1. `npm run build -- <version>`；
2. `npm run check`；
3. `npm test`；
4. UI/模板/宿主事件相关运行 `node scripts/test-browser.mjs`；
5. EJS 相关按需运行 `node scripts/test-ejs.mjs`；
6. 检查 diff/status；
7. 固定 loader 只引用自己的 `@<version>`；
8. receipt 与 bundle 对齐；
9. tag 指向同一通过检查的提交；
10. 未完成真实 SillyTavern/模型验收时明确写 `realHostVerified=false`，不得把自动化写成人工通过。
