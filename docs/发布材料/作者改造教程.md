# 给纯文字状态栏加上 LoreState

适用版本：`0.10.4` 固定远程组件。需要酒馆助手；本文不涉及旧原生 LoreState 扩展。首次尝试请复制角色卡并使用新聊天，避免两套状态维护同时运行。需要跟随开发时才切换到帖子中的 `main` 远程入口。

## 先用附件跑通

1. 导入帖子里的 `0.10.4` 远程脚本 JSON，或在酒馆助手的角色脚本中填入帖内固定版本 import。当前只使用远程版；需要试用尚未发布的开发修复时才切换到 `main`。
2. 在角色绑定的世界书中新建状态条目，把 `状态栏条目.txt` 分隔线之后的正文粘贴进去。
3. 打开角色聊天，从魔法棒进入「LoreState · 原型设置」，选择这本世界书和刚创建的条目。
4. 用文本编辑器打开 `状态栏模板.html`，复制完整 HTML 到设置中的 HTML 文本框，点击「预览 HTML（不保存）」。不要粘贴文件路径或 Markdown 代码围栏。
5. 点击「保存 HTML 并启用本聊天」。脚本会添加两条本卡正则；确认酒馆本卡局部正则已启用。
6. 正常开始一轮对话。首次有效 AI 状态需要包含所有栏目，之后只更新变化的栏目。HTML 中的示例文字只供预览，不会自动变成初始状态。

推荐在开场白后、第一次正式对话前配置。0 层开场白默认不参与状态建立；在已有聊天中首次启用时，不应期待自动迁移旧状态栏。

## 改造已有状态栏：文字规则和外观各改一处

假设原来要求 AI 每轮输出：

```text
【状态】
地点：……
衣着：……
身体状况：……
```

世界书里保留「地点记录什么」「什么情况下衣着改变」等创作规则，去掉每轮重抄上述完整状态表的要求，改成「输出格式遵循 LoreState 的协议，不额外输出旧状态表」。附件的条目可以作为参考。

原来负责抓取这张状态表并替换成 HTML 的正则，可以停用；其他与状态栏无关的正文美化正则保留。旧的“禁止发送以往整层 AI 消息”正则应停用，否则历史剧情仍然会被过滤。不要同时运行旧 QR 或脚本维护同一份状态。

原 HTML 可能通过正则捕获组填值：

```html
<h3>当前位置</h3><p>$1</p>
<h3>衣着</h3><p>$2</p>
```

改为明确的栏目绑定：

```html
<h3>当前位置</h3><p data-lore-field="地点"></p>
<h3>衣着</h3><p data-lore-field="衣着"></p>
```

脚本将完整文字填入绑定节点。`$1`、`{{地点}}` 或其他旧变量表达式不再需要。

标题应放在绑定节点外。不要写成 `<p data-lore-field="地点">地点：<span></span></p>`，因为填值会覆盖 p 内所有内容。绑定节点不能互相嵌套。

## 不想自己写 HTML，可以这样交给网页 AI

先在世界书中确定栏目，然后使用脚本的「生成并复制 HTML 制作提示词」。把该提示词和你希望的配色、排版一起交给网页 AI。也可以加上：

> 请改造我附上的状态栏 HTML，保留原有视觉风格。各项文字通过 data-lore-field 绑定，栏目为地点、衣着、身体状况。只使用静态 HTML/CSS，标题放在绑定节点外，不保留正则捕获组或旧变量语法。样式适应窄屏、允许长文字换行。返回完整 HTML。

本版不接受 script、事件属性、图片、外部字体、iframe、表单和 SVG；不要让网页 AI 生成“自动读变量”的 JavaScript。原生 details/summary 折叠可用。

## 怎么改栏目与皮肤

新卡可以在首次配置前，把附件中的「地点」「衣着」「身体状况」改成自己需要的栏目，并同步修改世界书描述。例如「地点」可以换成「所在区域」。

栏目名使用文字开头，后续可含文字、数字、下划线或连字符；不含空格和标点，最多 40 字符，总数 1～32 个。人物或物品列表目前作为一个栏目的多行文字，不设计嵌套标签。

**已有配置后，预设必须使用同一组栏目。** 标题、颜色、布局和栏目顺序可以变；不能通过换肤添加或删除栏目。真正修改栏目结构应在独立测试卡／脚本中重新配置。

保存新皮肤时：粘贴 HTML → 预览 → 填预设名称 →「另存为新预设」→ 选择该预设 →「应用所选预设」。另存不会立刻切换。覆盖当前预设会更新当前外观；删除当前预设前要先切换到另一份。

预设保存在随卡脚本数据中，本版没有独立的读者个人预设层。名称不可重复，最多 20 份。

## 看懂更新标签，方便纠错

这些示例供理解或手动编辑消息使用，不必再把整段教程加入世界书。模型的输出协议由脚本提供。

首次 AI 回复在正文后附上：

```xml
<LoreState mode="full">
<地点>城南的旧酒馆。</地点>
<衣着>灰色斗篷。</衣着>
<身体状况>有些疲惫，没有受伤。</身体状况>
</LoreState>
```

下一轮只换衣服：

```xml
<LoreState mode="delta">
<衣着>换上了深色雨衣。</衣着>
</LoreState>
```

未提及的栏目保持原样。变化的栏目写完整的新文字，例如原来列出三件物品，丢掉一件后应写剩余的完整列表，不能只写「少了一件」。

没有变化也需要输出完整的空更新块：

```xml
<LoreState mode="delta"></LoreState>
```

明确移除一个栏目的已存内容时，使用 `<衣着 action="remove"/>`；这不等于脱掉外套。如果只是衣着变化，仍应记录新的衣着描述。移除后 HTML 对应位置显示「尚未记录」。

每条有效 AI 回复只放一个 LoreState 块，首次 full 后使用 delta。文字中的 `<` 和 `&` 分别写成 `&lt;`、`&amp;`。不支持通过「继续」反复向同一条回复追加多个状态块。

如果更新报错，编辑对应 AI 楼层的原始标签并保存；仍有错误提示时点击「重新读取状态」。修改某一轮不会自动修正后续剧情，后面的有效增量也可能覆盖刚改的内容。

## 随卡发布前

保留脚本数据随卡导出的设置，将状态规则世界书与角色一起携带，确认局部正则也随卡保存。导出后在测试副本重新导入：检查世界书名称和条目关联、HTML 预设、脚本启用状态、正则和一次 full→delta 流程。

世界书重命名或条目变化后可能需要重新选择关联。完整的随卡往返仍属于本版待验收项，不要只凭自己正在使用的聊天正常就判断读者导入一定正常。

升级时只改原脚本的 import 版本，保留原脚本 ID 和数据；不要为了更新先删除脚本。发布附件不需要包含自己的聊天存档。
