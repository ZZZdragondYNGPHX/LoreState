# 给纯文字状态栏加上 LoreState · 0.13.0

适用当前固定版 **`0.13.0`**。需要 SillyTavern 与 Tavern Helper；本文只讲当前 Tavern Helper 脚本。

首次改造建议复制角色卡并使用独立测试聊天，只启用一份 LoreState。需要发给其他创作者或使用者做快速查阅时，可直接使用 [Discord 创作者 / 使用者参考](Discord帖子-创作者与使用者参考.md)。

## 1. 安装固定版

导入 [0.13.0 固定远程组件](../../prototype/dist/0.13.0/lorestate-script.json)，或使用：

```js
import 'https://testingcf.jsdelivr.net/gh/ZZZdragondYNGPHX/LoreState@0.13.0/artifact/bundle.js';
```

`main` 只用于开发，不要和固定版同时启用。

## 2. 把旧规则改成模块条目

当前 DataSchema 由**状态栏条目**定义，不再由 HTML 反推。可以直接复制 [当前模块条目附件](状态栏条目.txt) 或 [项目示例](../../prototype/module-example.txt)。

```text
【LoreState模块 v1】
【通用规则】
只记录正文已经确认的持久事实；猜测、计划和未发生事件不写成当前事实。

【公共栏目】
栏目：地点、时间
明确移动或剧情时间推进时更新。

【模块：人物】
栏目：身体状况、当前目标
受伤或恢复时更新身体状况；明确改变意图时更新当前目标。
```

删除旧世界书里“每轮重抄整张状态表”“输出另一套 `<状态栏>` 协议”“让 HTML / 正则负责保存状态”等要求。输出协议由 LoreState 当轮注入。

## 3. 明确绑定条目

1. 打开 **魔法棒 → LoreState → 规则配置**。
2. 选择世界书和状态栏条目。
3. 点击 **确认绑定状态栏条目**。
4. 再进入 **外观制作**。

确认绑定不会启用聊天、写状态或修改世界书活动规则。

## 4. 制作 Template API v2 外观

可在 **模型连接 → 管理 API 预设** 保存模型，然后用外观制作台生成 / 修改 HTML 草稿；也可粘贴 [当前模板附件](状态栏模板.html)、[旅途档案 HUD](../../prototype/example.html) 或 [紧凑日志](../../prototype/module-example.html)。

模板根：

```html
<html lang="zh-CN" data-lore-template="2">
```

公共字段使用 `data-lore-shared`；实体先用 `data-lore-each="模块名"` 建立区域，再用 `data-lore-field` 读取字段。HTML 只决定展示，不决定保存字段。完整合同见 [Template API v2](../HTML模板适配指南.md)。

## 5. 保存并开始

预览 / 应用外观后点击 **保存 HTML 并启用本聊天**。第一次有效状态回复建立 full，之后只提交发生变化的栏目。

一个栏目内部仍是完整当前值替换；新值要保留该栏目里仍成立的旧事实。

## 6. 结构性改栏目（0.12.3 起）

换颜色、布局、显示顺序不是 schema 变化，可以继续使用现有状态。

增删、改名模块或栏目属于 DataSchema 变化。0.12.3 起可在 **规则配置 → 聊天维护** 输入 `删除旧配置`，执行 **彻底删除旧配置**，随后重新绑定条目、制作 / 应用匹配新 schema 的 HTML、再启用聊天。

该操作会删除本脚本配置与当前聊天 LoreState 状态、快照、回档和更新绑定，但保留聊天正文、世界书和全局 API；不可撤销，重要数据先备份。

## 7. 0.13.0：核对规则与作者默认档案

0.13.0 的状态请求会先生成简短 `LoreStateReview` 核对摘要，再提交 v3 状态更新。需要额外强调某些字段何时变化时，在 **模型连接 → 状态更新绑定 → 自定义更新核对规则** 填写规则并保存。

如果角色卡需要带着统一的初始状态和字段约束发布，在 **初始档案与字段约束** 中预览后点击 **保存为新聊天默认配置**。这只保存作者默认配置，不会把当前聊天进度、快照和冷热档塞进角色卡。

## 8. 升级

从 `0.12.3` 升级到 `0.13.0`，已有 v3 状态、作者档案、快照和合法 v2 外观无需重建。升级后建议重新保存状态更新绑定；准备分享角色卡时再执行一次导出准备，让核对规则、更新默认值与规则副本完整写入随卡配置。

从 `0.11.0`～`0.12.2` 升级时，合法 v2 外观、v3 状态和快照同样无需因为版本号本身迁移。`0.10.6` 或更早旧 HTML 需要重制 v2 外观。

## 9. 准备角色卡导出

分享前先保存外观、自定义核对规则和作者默认档案，然后在 **规则配置 → 角色卡导出** 点击 **检查并准备角色卡导出**。工具会同步当前模块规则副本、校验当前 HTML 与作者默认档案、保存可移植更新默认值、刷新过滤正则并确认当前角色脚本的导出开关。

之后再使用酒馆本身导出角色卡，并在独立环境重新导入检查。API 密钥、个人连接和实际聊天状态不会随角色卡携带。完整边界见 [更新核对与随卡导出](../更新核对与随卡导出.md)。

## 10. 可选功能

- 独立状态模型 / 多协议 API：[额外模型与 API 预设](../额外模型与API预设.md)。
- 按状态驱动动态世界书：[EJS / 动态世界书](../EJS动态世界书.md)，需用户自行安装 ST-Prompt-Template。

## 发布前检查

至少验证：固定脚本版本、世界书与条目绑定、一次 full → delta、更新前核对、跨模块更新、刷新 / 切聊天、回档、Template API v2 外观、过滤规则、执行导出准备后再导出并重新导入；使用额外模型 / EJS 时再测真实服务与扩展组合。

自动化测试不等于真实 SillyTavern、实际模型、手机和长期游玩已经验收。
