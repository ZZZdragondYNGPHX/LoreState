# 给纯文字状态栏加上 LoreState · 0.12.1

适用当前固定版 **`0.12.1`**。需要 SillyTavern 与酒馆助手（Tavern Helper）；本文只讲当前 Tavern Helper 脚本，不涉及仓库根目录的旧原生扩展。

首次改造建议复制角色卡并使用独立测试聊天。只启用一份 LoreState：正常使用选择固定 `0.12.1`，只有明确要跟随开发时才使用 `main`。

## 1. 安装当前固定版

可以直接导入 [0.12.1 固定远程组件](../../prototype/dist/0.12.1/lorestate-script.json)，也可以在酒馆助手中新建角色脚本并填入：

```js
import 'https://testingcf.jsdelivr.net/gh/ZZZdragondYNGPHX/LoreState@0.12.1/artifact/bundle.js';
```

固定版不会随 `main` 变化。不要同时启用旧固定版、0.12.1 和 `main`。

## 2. 把旧状态栏规则改成模块条目

当前 DataSchema 由**状态栏条目**定义，不再由 HTML 反推。最省事的起点是直接复制 [当前模块条目附件](状态栏条目.txt) 或 [项目模块示例](../../prototype/module-example.txt)。

基本格式：

```text
【LoreState模块 v1】
【通用规则】
只记录正文已经确认的持久事实；猜测、计划和未发生事件不写成事实。

【公共栏目】
栏目：地点、时间
明确移动或剧情时间推进时更新。

【模块：人物】
栏目：身体状况、当前目标
受伤或恢复时更新身体状况；明确改变意图时更新当前目标。

【模块：物品】
栏目：持有者、完好状况
交付、拾取、遗失、损坏或修复时更新。
```

公共栏目适合地点、时间等整个场景共用的事实；不同模块可以拥有不同栏目，例如人物记录身体状况，物品记录持有者，国家记录外交，事件记录进展。

原世界书里“什么时候变化、什么算事实、未知怎么写”的创作规则可以保留；删除“每轮重抄整张状态表”“输出旧 `<状态栏>`”“让 HTML/正则负责保存状态”等旧要求。具体输出格式由 LoreState 每轮注入，不需要在世界书里再复制一套协议。

## 3. 0.12.1 首次绑定流程

在角色或聊天绑定的世界书中新建/选中状态栏条目，然后：

1. 打开 **魔法棒 → LoreState 设置**。
2. 选择准备使用的世界书与状态栏条目。
3. 点击 **确认绑定状态栏条目**。
4. 再进入 **外观制作**。

0.12.1 会保存这一步的条目选择；刷新列表或在设置/外观制作之间切页不会再默认跳到第一条。确认绑定本身不会启用聊天、改状态或修改世界书活动规则。

## 4. 制作 Template API v2 外观

推荐直接使用内置**外观制作台**：先在 API 预设页保存可用的模型连接，再从风格描述生成 HTML 草稿，或基于当前 HTML 继续改稿。生成结果只进入草稿，必须预览并显式应用后才会生效。

也可以直接粘贴 [当前模板附件](状态栏模板.html)、[旅途档案 HUD](../../prototype/example.html) 或 [紧凑日志](../../prototype/module-example.html)。自制模板必须以：

```html
<html lang="zh-CN" data-lore-template="2">
```

作为 v2 文档根。公共字段使用：

```html
<p data-lore-shared="地点"></p>
```

实体先声明模块区域，再读取该模块字段：

```html
<article data-lore-each="人物">
  <h3 data-lore-name></h3>
  <p data-lore-field="身体状况"></p>
  <p data-lore-field="当前目标"></p>
</article>
```

Template API v2 可以只显示部分字段、重复字段、为同一模块设置多个区域，并通过 `active/cold/all`、count、empty、limit 等声明式接口安排冷档。**HTML 只决定怎么显示，不决定保存哪些字段。**

完整语法见 [HTML 模板适配指南](../HTML模板适配指南.md)。

## 5. 安全边界

外观只接受受限的静态 HTML/CSS。不要加入自定义 JavaScript、事件属性、iframe、SVG、表单、外链图片/字体、`url()`、`@import` 或“自动读变量”的脚本。

动态状态始终作为文字绑定，不把状态内容当作可信 HTML 执行。样式可以使用允许范围内的 CSS、原生 `details/summary`、响应式布局，以及 0.11.1 起提供的字段条件显隐和 class 映射。

## 6. 保存并开始聊天

确认模板预览正确后，在设置中点击 **保存 HTML 并启用本聊天**。脚本会按当前流程安装/维护本卡所需的显示过滤与提示词过滤规则；原始消息中的 LoreState 更新仍保留，供回放和诊断使用。

第一次有效状态回复需要建立完整状态，之后只提交发生变化的栏目。概念示例：

```xml
<LoreState version="3" mode="full">
  <Shared><地点>白帆港</地点><时间>第三天清晨</时间></Shared>
  <Entity id="P1" type="人物" name="爱丽丝" identity="港口向导" mode="full" presence="active">
    <身体状况>健康。</身体状况>
    <当前目标>带领队伍前往旧灯塔。</当前目标>
  </Entity>
</LoreState>
```

下一轮只改变地点和人物状态时，只提交变化：

```xml
<LoreState version="3" mode="delta">
  <Shared><地点>旧灯塔入口</地点></Shared>
  <Entity id="P1" mode="delta"><身体状况>右手轻微擦伤。</身体状况></Entity>
</LoreState>
```

实际生成时必须以当轮 LoreState 注入的协议、编号和读取凭据为准；上面的 XML 只用来理解 full/delta，不要把它作为另一套固定世界书格式硬塞给模型。

一个栏目内部仍是**完整当前值替换**。例如原值“持有钥匙，左臂受伤”，归还钥匙后如果伤势仍存在，新值仍要保留“左臂受伤”，不能只写“已归还钥匙”。

## 7. 改栏目与换皮肤不是一回事

换颜色、布局、显示顺序、隐藏部分字段，不会修改 DataSchema，可以继续使用原聊天状态。

增删、改名模块或栏目属于 schema 变化。现有配置有结构保护，不应靠换 HTML 偷改数据结构；建议在独立测试配置和新聊天中验证后再迁移使用。

从 `0.11.0` / `0.11.1` / `0.12.0` 升级到 `0.12.1`，v3 状态、快照和合法 v2 外观无需迁移。若从 `0.10.6` 或更早版本升级，旧 HTML 原文会保留，但需要重新制作 Template API v2 外观。

## 8. 可选：按状态驱动动态世界书

需要“好感度落在某一区间时才输出对应行为规则”之类的动态世界书，可以额外启用 ST-Prompt-Template，并使用 LoreState 的 EJS 只读桥接。它读取当前冻结快照，不创建第二套状态，也不写回 LoreState。

详见 [EJS / 动态世界书](../EJS动态世界书.md)。不安装 Prompt Template 时，LoreState 的普通状态记录、回放和外观功能仍可正常使用。

## 发布前检查

在测试副本中至少检查一次：固定脚本版本、世界书与条目绑定、Template API v2 外观、一次 full → delta、刷新/切聊天恢复、局部过滤规则、脚本数据随卡导出，以及导出后重新导入。

自动测试通过不代表真实 SillyTavern、实际模型、手机和长期游玩已经验收。遇到问题时优先记录 LoreState 版本、操作步骤、错误楼层，以及去除隐私后的标签或诊断信息。
